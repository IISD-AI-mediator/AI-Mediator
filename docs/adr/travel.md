# 여행 조율 서비스의 아키텍처 결정

## ADR-012 · 방 개설과 초대 링크 공유

| 항목 | 내용 |
| --- | --- |
| Title | ADR-012 · 방을 만든 뒤 해당 방의 초대 링크를 발급해 공유한다 |
| Status | Approved |
| Context | 최초 방문자는 공용 코드를 얻을 경로가 없었다. Render에서 일반 생성 요청은 403으로 끝났고, 로컬에서 생성을 마쳐도 바로 개인 조건 화면으로 이동했다. |
| Decision | 로컬과 Render 모두 닉네임과 방 설정으로 개설한다. 기존 저장소가 발급하는 무작위 방 식별자와 방별 참가자 쿠키를 그대로 사용한다. 방장은 생성 직후 `/r/<invite>/share`에서 참가용 `/r/<invite>` 주소를 복사한다. 전용 주소를 두어 방장이 새로고침해도 공유 화면을 복원하고, 기존 참가용 주소로 접속하면 각자 입장하거나 진행 중인 단계로 돌아간다. |
| Consequence | 코드 발급·전달을 운영자가 맡을 필요가 없다. 링크를 받은 사람은 빈 좌석에 입장할 수 있다. 누구나 방을 만들 수 있으므로 기존 전체 방 개설 한도가 공개 서비스 전체에 적용된다. |
| Governance | 리뷰어는 생성 재시도·방별 권한·정원·배포 설정을 확인한다. 테스터는 분리된 두 브라우저 세션에서 실제로 복사한 주소로 같은 방에 입장하고 서로 다른 좌석을 받는지 검증한다. |
| Notes | ADR-001의 저장소와 세션 계약을 사용한다. [화면 흐름](../design/travel-flow.md) · [ROOM-05 구현 기준](../design/travel-implementation.md#room-05--방-개설과-초대-링크-공유) |

## ADR-011 · 첫 제안의 앞말과 뒷말을 모델이 작성할 수 있게 한다

| 필드 | 내용 |
|---|---|
| Title | ADR-011 · 확정값 양쪽의 자유 작성문을 독립된 첫 제안 후보로 사용한다 |
| Status | Approved |
| Context | OPEN-04의 두 번째 자연·대조 실행에서 작성기가 금액이나 교통수단을 추측하거나 같은 설명을 반복했고, 검토기는 상한의 동의어를 추가 주장으로 보거나 원문 인용부호를 잃었다. 첫 제안에서 행동은 자기 제안 하나로 정해져 있다. |
| Decision | 기존 첫 제안 경로에 값 앞뒤를 모델이 직접 쓰는 완결된 짧은 후보를 추가한다. 서버는 이미 승인한 값만 중간에 한 번 넣는다. 문구나 어미를 서버가 고르는 복구와 생성 출처를 구별한다. 첫 제안 검토에서는 자기 제안·순수 감탄·상한의 동치와 근거 없는 비교·타인의 의견에 대한 반응을 구분하며, 실제 게시할 전체 문장과 기준문의 인용을 검증한다. |
| Consequence | 모델이 지명을 추측하거나 값 표식을 빠뜨려도 다른 독립 후보를 검증할 수 있다. 후보별 검증 횟수에는 한도가 생기며 기존 복구와 개인정보 보호는 계속 필요하다. |
| Governance | 자연 방과 실제 실패한 예산·택시 및 활동·택시 대조에서 생성 필드와 값으로 게시 문장을 복원한다. 검토 흔적, 두 세션 원문, 원래 조건, 검토 오류·외부 사실 추가 시 거절과 개인정보를 확인한다. |
| Notes | ADR-010을 보완한다. 기존 판정·토론·기억 경로는 ADR-008, ADR-009를 따른다. |

## ADR-010 · 첫 제안에는 제안 전용 작성 지시와 재작성 사유를 전달한다

| 필드 | 내용 |
|---|---|
| Title | ADR-010 · 첫 공개 제안의 표현을 확정된 조건 하나에 근거해 작성한다 |
| Status | Approved |
| Context | OPEN-04. 직전 방에서 서윤은 회계 담당자 역할을 비용 효율성의 근거로 해석했다. 민재는 아직 듣지 않은 의견에 찬반을 표시했다. 두 번째 요청은 실패 원인 없이 재작성만 요구했다. |
| Decision | 병렬 첫 제안에만 전용 작성 계약을 사용한다. 원래 안건·행동·값과 사용자가 직접 쓴 페르소나를 전달하고, 독립된 첫 화자라는 상황에서 그 사람의 말로 제안 하나를 쓰게 한다. 실패하면 서버가 판단한 사유 범주와 고칠 방향을 주고 원자료로부터 다시 작성시킨다. 문장 일부를 잘라 쓰거나 인물별 문구 목록으로 대체하는 방식은 쓰지 않는다. |
| Consequence | 근거를 만들지 않고도 두 화자의 문체를 살릴 수 있다. 생성 결과에는 여전히 값·행동·개인정보·의미 검증이 필요하며, 제공자 오류나 반복 거절에는 기존 복구 경로가 남는다. |
| Governance | 최초 공개문 두 건의 출처, 생성 응답과 게시 전문, 별도 의미 검토, 제안 당시 조건, 비공개 지시 처리, 양쪽 화면을 실측한다. 이전 실패 원문으로 거짓 수락과 무의미한 동일 재시도를 검사한다. |
| Notes | [이전 실제 방](../test/turn-memory-gemini.md) · ADR-008, ADR-009 |

## ADR-009 · 공개된 대화에서 화자의 앞선 입장을 복원한다

| 필드 | 내용 |
|---|---|
| Title | ADR-009 · 방의 공개 발언을 다음 협상과 발언 생성의 짧은 문맥으로 사용한다 |
| Status | Approved |
| Context | TURN-03. 같은 금액을 지키는 두 차례의 행동이 모두 첫 제안처럼 렌더링됐다. 모델이 잘 쓴 제안 뒤에 새 이유를 붙였고, 두 번 모두 동일한 복구문이 게시됐다. |
| Decision | 같은 방에서 이미 게시된 발언만 제한된 길이로 제공한다. 자신의 앞선 입장과 현재의 방어 행동이 일치하면 재확인으로 표현하고, 값 변경과 양보는 그대로 표현한다. 공개 이벤트와 입장 식별 정보는 같은 저장 트랜잭션에서 확정한다. 문맥은 표현의 참고 자료이며 새 조건을 승인할 권한은 없다. |
| Consequence | 모델 호출 사이의 시간이나 작업자 재시작과 무관하게 완료된 발언을 재사용한다. 표현 검토에서 독립적으로 성립하는 발언만 골라 다시 검증할 수 있다. 기존 데이터에 입장 식별 정보가 없으면 과거에 했다고 단정하지 않는다. |
| Governance | 방·화자 격리, 생략·변경·양보, 공개 문장만으로 만든 기억, 복구 후의 재확인, 값·행동의 정확성, 잘린 문장의 의미 반전을 독립 검토한다. 동일 실제 방과 같은 안건을 두 번 말하는 실제 모델 호출의 공개 결과를 기록한다. |
| Notes | ADR-004, ADR-008을 보완한다. [수정 전 발언 3번과 7번](../test/live-two-person-gemini-after.md) |

## ADR-008 · 참가자 의사와 AI 제안의 출처를 판정과 공개 발언에 보존한다

| 필드 | 내용 |
|---|---|
| Title | ADR-008 · 여행 조건의 출처와 검증 범위를 최종안까지 보존한다 |
| Status | Approved |
| Context | PAIR-02. 실제 2인 방에서 AI가 제안한 접근 시설이 합의로 표시되고, 표현을 바꾸며 새 조건이 생겼다. 활동 한 건의 미검증이 다른 날의 활동까지 가렸다. 판사 전송 7건 중 4건이 시간 초과됐다. |
| Decision | 기존 LangGraph와 방 저장 경계를 유지한다. 서버가 참가자 입력과 승인된 변경에 연결되는 결정, AI 추천, 의견 충돌, 증거 부족을 구분한다. 활동은 날짜별로 검토하고 확인되지 않은 후보에 표시한다. 발언은 사용자 페르소나로 생성하되 정확한 값·행동과 추가 주장 유무를 검사하고 고칠 기회를 제한한다. 판사는 필요한 정보와 낮은 추론 지연 설정으로 같은 모델에서 판단한다. |
| Consequence | AI 제안도 여행안에 남길 수 있으며 누가 동의했는지 과장하지 않는다. 일부 날짜가 미정이어도 다른 날의 후보를 볼 수 있다. 발언 재생성은 시간이 들 수 있고 제공자 지연 및 검증 실패가 지속되면 기존 복구 경로가 필요하다. |
| Governance | 독립 리뷰에서 조건의 출처, 비공개 지시 보호, 미검증 후보의 표시, 기존 저장방 조회 및 재시도를 확인한다. 같은 두 사용자 세션으로 전체 소요 시간과 개별 판사 지연을 측정한다. |
| Notes | ADR-002, ADR-004, ADR-006을 보완한다. Gemini 3.8 Flash에서 사용하는 추론 수준과 실제 지연은 각각 제공자 명세와 전송 기록으로 확인한다. [Google의 모델별 추론 설정](https://aistudio.google.com/docs/thinking#thinking-levels) · [이전 실측](../test/live-two-person-gemini.md) |

## ADR-001 · 방 단위 트랜잭션과 단일 웹 서비스

| 항목 | 내용 |
| --- | --- |
| Title | ADR-001 · 방 단위 트랜잭션과 단일 웹 서비스 |
| Status | Approved |
| Context | 네 명 안팎이 같은 초대 링크로 약 20회 시험한다. 마지막 두 사람이 동시에 준비를 눌러도 조율은 한 번만 시작해야 한다. 운영 담당 인력과 유료 예산은 정해지지 않았다. |
| Decision | Windows의 Python 3.13에서 웹·조율 실행기를 한 서비스로 운영한다. 로컬은 SQLite, 무료 클라우드는 재시작에 대비해 PostgreSQL을 쓴다. 같은 출처에서 HTML과 JSON API를 제공하고, 짧은 주기로 방 변경을 읽는다. SQLite 트랜잭션 또는 PostgreSQL 행 잠금으로 방을 갱신한다. |
| Consequence | 팀원의 설치 부담과 구성 비용이 낮다. 웹 프로세스 한 개에서 시작하며, 무료 호스팅은 첫 요청이 지연될 수 있다. 상태를 DB에 남겨 새로고침과 프로세스 재시작을 처리한다. |
| Governance | 리뷰어는 소유권 검증, 정원과 시작 전이의 원자성, 저장 중 오류를 확인한다. 테스터는 서로 다른 브라우저, 동시 준비, 재시작 후 상태를 비교한다. |
| Notes | [동시성과 재시작 계약](../design/travel-implementation.md#동시성과-재시작-계약)에 요청 키, 저장된 단계, 임대 만료, 원자적 발언 저장을 정의했다. [무료 호스팅 사양](https://render.com/docs/free) |

## ADR-002 · 개인별 서브그래프와 결정자의 제한된 재조율

| 항목 | 내용 |
| --- | --- |
| Title | ADR-002 · 개인별 서브그래프와 결정자의 제한된 재조율 |
| Status | Approved |
| Context | 과제는 복수 모델, 외부 도구 호출, 상태를 이용한 반복과 조건 분기를 요구한다. 실제 여행에서는 검색 당시 가격과 팀원의 필수 조건을 구분해야 한다. |
| Decision | 생성자가 확정 조건에서 정원만큼 개인 에이전트의 역할을 만든다. 각 개인의 조율 그래프가 필요한 검색을 서브 에이전트에 위임하고 근거를 받아 협상한다. 결정자는 별도 Gemini 모델로 근거와 중요도, 이전 합의, 대안을 검토한다. 미합의 시 파이트로 분기하고 다음 턴 직전에 본인 지시를 읽는다. 종료 횟수를 정하고 상충하는 필수 조건과 조회 실패는 결과에 표시한다. |
| Consequence | 라운드별 잠정 결정과 근거의 변화를 재현할 수 있다. 외부 API의 오류·할당량에 따라 일시정지나 제한된 검색 결과가 발생한다. 팀원은 재시도를 선택할 수 있다. |
| Governance | 코드 리뷰에서 실제 StateGraph, 두 모델 호출과 검색 결과 경로를 추적한다. 테스터는 합의·갈등 양 경로, 지시 전달, 결정 변경과 한도 종료를 검증한다. |
| Notes | [모델과 근거 계약](../design/travel-implementation.md#모델과-근거-계약)에 역할별 모델, 가격 검증, 고정 값·필수 조건의 최종 검사를 정의했다. [화면 설계](../design/travel-flow.md), [LangGraph 워크플로](https://docs.langchain.com/oss/python/langgraph/workflows-agents) |

## ADR-003 · 두 모드의 판단과 최종 결정을 한 판사 에이전트에 맡긴다

| 항목 | 내용 |
| --- | --- |
| Title | ADR-003 · 조율과 파이터 모드의 판사 에이전트 |
| Status | Approved |
| Context | 첫 판단과 파이터 모드 직후의 재판단은 모두 `judge`를 거치지만 첫 판단과 첫 토론의 회차 번호가 같다. 모델은 어느 단계인지 전달받지 못하고, 화면은 최종 결정을 누가 내렸는지 밝히지 않는다. |
| Decision | 기존 `judge` 노드가 모드, 남은 토론 횟수, 좌석별 최신 의견·근거, 이전 판단을 받아 매번 여행안을 결정한다. 마지막 토론 뒤에는 가능한 항목을 확정하고, 검증을 통과한 결정을 기존 `final` 노드가 한 번 게시한다. 별도의 최종 모델 호출은 같은 자료로 다른 판결이 생기고 재시도 비용이 늘어 제외했다. |
| Consequence | 두 모드에서 같은 기준을 적용하고 최초 조율과 첫 토론을 구분할 수 있다. 저장된 단계명, 요청 필드, 프리셋 값과 모델 설정 키는 호환된다. 공개 화면에서는 과거 기록의 진행자도 판사 에이전트로 식별한다. |
| Governance | 코드 리뷰에서 좌석별 의견 전달, 비공개 지시 보호, 공개 이력의 호환성을 확인한다. 독립 시험에서 즉시 결정, 발언 후 결정 변경, 필수 조건 충돌, 이전 방 재접속과 재시도를 확인한다. |
| Notes | ADR-002의 개인별 서브그래프와 재조율 횟수를 사용한다. [화면 흐름](../design/travel-flow.md) · [구현 기준](../design/travel-implementation.md#trip-02--판사-에이전트) |

## ADR-004 · 화자의 자유 입력으로 공개 발언을 생성한다

| 항목 | 내용 |
| --- | --- |
| Title | ADR-004 · 개인 에이전트와 판사의 발언에 작성자가 지정한 페르소나를 적용한다. |
| Status | Approved |
| Context | PERS-01. 종전에는 자유 입력을 다섯 가지 표현 유형으로 분류했다. 첫 제안에는 모든 참가자가 같은 말투를 사용했다. 참가자가 직접 묘사한 성격과 말투가 첫 제안부터 드러나야 한다. |
| Decision | 실제 발언을 만드는 모델 요청에 해당 화자의 자유 입력 원문, 기본 성향과 세 수치, 이미 결정된 공개 발언 내용을 전달한다. 모델은 이 맥락에서 한국어 문장을 작성한다. 서버는 제안값을 보존하고, 생성된 문장이 원래 행동과 같은 뜻인지 공개 내용만으로 별도 검사한다. 협상 행동과 여행안은 기존 정책으로 결정하고, 검색에는 필요한 여행 조건만 전달한다. |
| Consequence | 같은 제안도 화자마다 다르게 설명할 수 있다. 발언 생성과 의미 검사에 추가 호출과 지연이 생긴다. 긴 인용구가 발언에 그대로 들어가면 화자가 공개적으로 사용하라고 지정한 구절인지도 확인한다. 생성이나 검사에 실패하면 검증된 내용으로 기본 발언을 게시한다. |
| Governance | 독립 시험에서 첫 제안, 개인 토론 발언, 판사의 즉시 합의·재판단·토론 개시 안내의 발언 요청과 공개 이력을 대조한다. 다른 참가자의 입력이 전달되는지, 말투만 변경했을 때 판단이 달라지는지, 모델 오류 후에도 합의가 게시되는지 확인한다. |
| Notes | ADR-002, ADR-003의 판단·복구 계약을 적용한다. [화면 흐름](../design/travel-flow.md) |

## ADR-005 · 여행 조율 단계별 모델 지시문을 한 모듈에서 관리한다

| 항목 | 내용 |
| --- | --- |
| Title | ADR-005 · 조율, 근거 검색, 공개 발언의 모델 지시문 |
| Status | Approved |
| Context | PROMPT-01. 여러 호출부에서 한국어 지시문을 각각 작성하며, 일부 출력 예시는 실제 JSON으로 해석할 수 없다. 역할마다 제공되는 정보와 결과를 읽는 코드가 다르다. |
| Decision | 시스템 지시문은 의존성 없는 Python 모듈에 둔다. 역할별로 사용할 정보와 결정 기준, 부족한 정보의 처리, 응답 형식을 기술한다. 방 데이터와 사용자의 자유 입력은 기존 호출부에서 별도의 사용자 메시지로 전달한다. |
| Consequence | 프롬프트 전체를 함께 검토할 수 있고, 호출부에서 각 결과가 어떻게 사용되는지 추적할 수 있다. 검색 인용 형식이나 협상 행동 필드가 바뀌면 해당 프롬프트도 함께 검토한다. |
| Governance | 코드 리뷰에서 지시문과 실제 입력·응답 처리기를 대조한다. 시험에서는 그래프와 검색·발언 경로에서 모델에 전달한 지시문과 사용자 메시지를 확인하고 기존 협상 회귀 시험을 실행한다. |
| Notes | ADR-002의 검색·협상, ADR-003의 판정, ADR-004의 페르소나 계약에 적용한다. |

## ADR-006 · 인용문의 의미와 필수 활동 충족 여부를 모델이 판정한다

| 항목 | 내용 |
| --- | --- |
| Title | ADR-006 · 검색 근거와 활동 합의의 의미 판정 |
| Status | Approved |
| Context | SEM-01. 기존 서버가 일반 라멘 판매를 채식 라멘의 근거로 인정하고, 두 필수 활동을 ‘후’로 연결한 확정 일정을 미합의 처리했다. 인용의 추적 가능성과 예산·권한 검사를 유지하면서 같은 의미의 표현을 일관되게 다뤄야 한다. |
| Decision | 검색 1회에서 얻은 단일 출처 인용 구간을 모아 개인 모델이 요청 조건 충족 여부를 판단한다. 서버가 지정한 구간 식별자로만 판정을 연결하며, URL·통화·금액·날짜·시간 등 구조로 검증할 수 있는 값은 서버가 확인한다. 판사 모델은 실제 제안과 유효한 일정에서 각 필수 활동의 충족 여부를 판단한다. 공개 발언에서 가격을 확인하겠다는 말과 새 가격을 보장하는 말은 기존 의미 검토가 구별한다. |
| Consequence | 출처 검토에 추가 모델 호출이 생긴다. 증거 부족·잘못된 응답·검토 실패를 합의나 확인의 근거로 쓸 수 없다. 현재 형식의 판단을 저장해 조회나 복구 때 모델을 호출하지 않는다. 이전 형식의 출처는 보존하고 새로운 검증을 거치기 전에는 확인이 필요한 근거로 표시한다. |
| Governance | 코드와 실행 시험에서 출처를 바꿔 붙일 수 없는지, 필수 활동을 하나만 택한 안이 합의 처리되지 않는지, 모델 장애에서도 방장 고정값·예산·비공개 정보가 보호되는지 확인한다. |
| Notes | [구현 계약](../design/travel-implementation.md#sem-01--모델의-의미-판정) · ADR-002, ADR-003, ADR-004, ADR-005 |

## ADR-007 · 로컬 Gemini 키를 앱과 제공자 점검에 연결한다

| 항목 | 내용 |
| --- | --- |
| Title | ADR-007 · 로컬 Gemini 키의 조회 위치와 우선순위 |
| Status | Approved |
| Context | KEY-01. 로컬 저장소의 `.env`에 키가 있어도 앱과 제공자 점검은 프로세스 환경만 읽어 키를 찾지 못했다. |
| Decision | 앱 설정에서 명시한 키, 프로세스의 `GEMINI_API_KEY`, 프로젝트 루트 `.env`의 같은 항목 순으로 사용한다. 파일은 서버에서 표준 dotenv 파서로 읽고 프로세스 환경을 수정하지 않는다. 일반 실행과 WSGI의 앱 팩토리 및 기존 제공자 점검이 같은 조회 방식을 쓴다. Waitress가 없으면 이미 만든 앱을 Werkzeug 개발 서버에 직접 전달한다. 이 경로에서도 Flask의 자동 dotenv 탐색을 거치지 않는다. |
| Consequence | 로컬에서는 한 번 저장한 키를 다음 실행에도 사용한다. 프로세스에 명시한 빈 값도 우선하며, 파일이나 키가 없어도 앱은 시작하고 기존 모델 오류를 표시한다. |
| Governance | 가상 키로 설정 우선순위·다른 작업 디렉터리·파일 부재·Flask 대체 경로·점검 실행 조건을 시험하고, 실제 호출은 응답 상태만 기록한다. |
| Notes | 기존 모델 선택과 역할은 ADR-005와 ADR-006을 따른다. [로컬 키와 실제 제공자 검증 기록](../test/local-gemini.md) |
