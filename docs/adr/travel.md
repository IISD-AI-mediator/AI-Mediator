# 여행 조율 서비스의 아키텍처 결정

## ADR-001 · 방 단위 트랜잭션과 단일 웹 서비스

| 항목 | 내용 |
| --- | --- |
| Title | ADR-001 · 방 단위 트랜잭션과 단일 웹 서비스 |
| Status | Approved |
| Context | 네 명 안팎이 같은 초대 링크로 약 20회 시험한다. 마지막 두 사람이 동시에 준비를 눌러도 조율은 한 번만 시작해야 한다. 운영 담당 인력과 유료 예산은 정해지지 않았다. |
| Decision | Windows의 Python 3.13에서 웹·조율 실행기를 한 서비스로 운영한다. 로컬은 SQLite, 무료 클라우드는 재시작에 대비해 PostgreSQL을 쓴다. 같은 출처에서 HTML과 JSON API를 제공하고, 짧은 주기로 방 변경을 읽는다. SQLite 트랜잭션 또는 PostgreSQL 행 잠금으로 방을 갱신한다. |
| Consequence | 팀원의 설치 부담과 구성 비용이 낮다. 웹 프로세스 한 개에서 시작하며, 무료 호스팅은 첫 요청이 지연될 수 있다. 상태를 DB에 남겨 새로고침과 프로세스 재시작을 처리한다. |
| Governance | 리뷰어는 소유권 검증, 정원과 시작 전이의 원자성, 저장 중 오류를 확인한다. 테스터는 서로 다른 브라우저, 동시 준비, 재시작 후 상태를 비교한다. |
| Notes | [동시성과 재시작 계약](../implementation/travel.md#동시성과-재시작-계약)에 요청 키, 저장된 단계, 임대 만료, 원자적 발언 저장을 정의했다. [무료 호스팅 사양](https://render.com/docs/free) |

## ADR-002 · 개인별 서브그래프와 결정자의 제한된 재조율

| 항목 | 내용 |
| --- | --- |
| Title | ADR-002 · 개인별 서브그래프와 결정자의 제한된 재조율 |
| Status | Approved |
| Context | 과제는 복수 모델, 외부 도구 호출, 상태를 이용한 반복과 조건 분기를 요구한다. 실제 여행에서는 검색 당시 가격과 팀원의 필수 조건을 구분해야 한다. |
| Decision | 생성자가 확정 조건에서 정원만큼 개인 에이전트의 역할을 만든다. 각 개인의 조율 그래프가 필요한 검색을 서브 에이전트에 위임하고 근거를 받아 협상한다. 결정자는 별도 Gemini 모델로 근거와 중요도, 이전 합의, 대안을 검토한다. 미합의 시 파이트로 분기하고 다음 턴 직전에 본인 지시를 읽는다. 종료 횟수를 정하고 상충하는 필수 조건과 조회 실패는 결과에 표시한다. |
| Consequence | 라운드별 잠정 결정과 근거의 변화를 재현할 수 있다. 외부 API의 오류·할당량에 따라 일시정지나 제한된 검색 결과가 발생한다. 팀원은 재시도를 선택할 수 있다. |
| Governance | 코드 리뷰에서 실제 StateGraph, 두 모델 호출과 검색 결과 경로를 추적한다. 테스터는 합의·갈등 양 경로, 지시 전달, 결정 변경과 한도 종료를 검증한다. |
| Notes | [모델과 근거 계약](../implementation/travel.md#모델과-근거-계약)에 역할별 모델, 가격 검증, 고정 값·필수 조건의 최종 검사를 정의했다. [화면 설계](../design/travel-flow.md), [LangGraph 워크플로](https://docs.langchain.com/oss/python/langgraph/workflows-agents) |
