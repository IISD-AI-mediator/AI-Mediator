# PROMPT-01 · 여행 에이전트의 모델 호출 검증

2026-11-27, 기준 커밋 `213567c5046e85bc906b49f8f2b692b306bcd2c5`의 작업 트리에서 검증했다. Windows, Python 3.11.9, Flask 3.1.1, LangGraph 1.2.15, SQLite 3.45.1을 사용했다. [설계 결정 ADR-005](../adr/travel.md#adr-005--여행-조율-단계별-모델-지시문을-한-모듈에서-관리한다) · [판사 검증](judge.md) · [페르소나 검증](persona.md)

## 모델에 도달한 요청

두 참가자가 각각 택시와 대중교통을 필수로 지정한 방에서 생성, 준비, 토론, 개인 지시 제출, 최종 판정까지 실행했다. 두 세션의 쿠키, SQLite, 컴파일한 그래프와 Gemini 요청 직렬화기를 사용했다. 외부 HTTP 응답은 테스트에서 제공했다. 요청의 역할은 사용자 데이터에 포함된 항목으로 식별하고, 실제 송신 모델과 `systemInstruction`을 대조했다. [호출 테스트](../../tests/test_agent_prompts.py)

| 역할 | 확인한 요청과 결과 |
| --- | --- |
| 좌석별 임무 배정, 개인 조건 해석, 개인 여행 제안 | 개인 모델에 각각 다른 지시문이 전달됐다. 좌석 목록, 담당 항목과 개인 프로필, 검색 근거를 받는 호출을 구분했다. |
| 개인 토론 | 참가자가 “내 예산 상한을 70만 원으로 올려 줘.”를 제출했다. 개인 모델에 원문과 접수 번호 1, 이전 50만 원과 `important`가 전달됐다. 대역은 새 상한과 접수 번호, 기존 중요도를 반환했다. 다음 판사 입력에서 이 참가자의 70만 원·`important`를 확인했고 최종 예산도 70만 원이었다. 다른 역할의 입력에서 이 개인 지시가 발견되지 않았다. |
| 판사 | 판사 모델에 두 좌석의 제안과 남은 토론 횟수 1, 0이 차례로 전달됐다. 기존 회귀 시험에서는 마지막 회차에 필수 이동수단 충돌이 `unresolved`, 운임 근거 부족이 `verify`로 남았다. |
| 항공, 식당, 숙소, 활동 검색 | 네 종류의 입력을 실제 검색 함수에 전달했다. 검색별 지시문과 여행 조건, Google 검색 도구 설정을 확인했다. 일치하는 단일 출처를 제공하자 각각 640,000 KRW 운임, 요청한 지점의 메뉴, 숙소 소재지, 산책 장소 소재지가 확인됐다. 방의 개인 서브그래프에서도 식당 검색을 관찰했다. |
| 공개 발언, 공개 인용 허용 판정, 의미 보존 검토 | 공개 발언의 사용자 메시지에 화자의 자유 입력 원문과 수치가 들어갔다. 참가자 발언은 개인 모델, 판사 발언은 판사 모델에 전달됐다. 인용 허용 판정에는 해당 화자의 페르소나와 인용 후보만 들어갔다. 허용된 문구가 공개 제안에 나타났고 의미 보존 검토에는 원래의 공개 메시지와 후보 발언만 전달됐다. |

검색은 인용 메타데이터를 읽었고, 나머지 호출은 JSON 객체를 요청했다. 기존 페르소나 시험에서 금지한 인용·개인 지시와의 중복·의미 변경·검토 오류는 원래 공개 메시지로 복구됐다. 이 시험의 판정 응답은 대역이 제공했다. [공개 발언과 복구 사례](../../tests/test_persona.py)

## 근거를 확인할 수 있는 범위

동일한 인천–오사카 오전 왕복, 640,000 KRW 인용을 실제 검색 처리기에 넣었다. 세금 포함·수하물 명시·단일 출처는 `observed`, 세금 별도 또는 두 출처가 연결된 구간은 `verify`였다. 같은 지점의 삼겹살 판매는 `observed`, 서울 지점에서만 판다는 발췌문은 `verify`였다. [운임 조건과 지점 검증 사례](../../tests/test_quote_and_branch_conditions.py)

식당 지시문은 메뉴와 식이 조건을 같은 지점·같은 요리에서 확인하도록 한다. 부분 근거를 전할 때에는 확인이 필요한 조건까지 같은 인용 문장에 담도록 했다. `food="채식 라멘"`을 요청하고 지점과 출처를 고정한 세 가지 입력을 실제 검색 처리기에 전달했다. [식당 지시문](../../travel_app/prompts.py) · [검색 근거 처리](../../travel_app/models.py)

| 단일 인용 구간 | 결과 |
| --- | --- |
| 난바역 지점은 채식 라멘을 판매합니다. | `observed` |
| 난바역 지점은 라멘을 판매하지만 채식 재료와 조리 방식은 확인이 필요합니다. | `verify` |
| 난바역 지점은 라멘을 판매합니다. | `observed` |

세 번째 사례에서 검색 모델이 식이 조건을 누락하면 기존 처리기는 일반 라멘 판매도 일치로 받아들인다. 이 경우 `observed` 상태만으로 채식 여부를 입증할 수는 없다.

이번 검증에서는 실제 Gemini에 요청하지 않았다. 모델이 일반적인 예산 변경 문장에서 중요도를 올바르게 유지하는 빈도, 말투의 자연스러움, 실제 검색 문서에서의 인용 정확도는 측정하지 않았다.
