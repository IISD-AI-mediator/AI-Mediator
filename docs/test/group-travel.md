# 4인 여행방 통합 시험

Windows에서 네 명이 한 방을 끝까지 사용하는 과정을 20회 반복했다. 바로 합의한 방 10개와 파이트 모드에서 개인 지시가 반영된 방 10개가 모두 최종 여행안을 저장했다. 별도 실행한 저장소 전체 테스트는 6개가 통과했다.

| 확인 항목 | 입력과 관찰 결과 |
| --- | --- |
| 초대와 권한 | 팀 코드 없이 방을 만들면 403을 받았다. 같은 생성 요청을 다시 보내면 같은 방이 열렸다. 초대 페이지에서 네 개의 독립 쿠키 세션이 각자 다른 개인 에이전트를 받았다. |
| 전원 준비 이벤트 | 두 명이 준비한 동안에는 대기 상태였다. 마지막 두 명이 동시에 제출한 뒤 자동으로 조율이 시작되고 개인 제안은 정확히 네 건 발생했다. |
| 확정 조건과 가능한 합의 | 부산을 서울로 바꾸려는 참가자 입력은 409를 받았다. 결정자가 서울을 제안해도 부산이 유지됐다. 두 필수 활동은 첫날 박물관 관람과 둘째 날 해변 산책으로 각각 보존됐다. |
| 서칭 에이전트 | 한 참가자가 삼겹살을 요청했다. 검색 호출에 실제로 전달된 숙소와 음식이 해운대역·삼겹살인지 확인했다. 시험용 검색 응답에 포함한 메뉴 출처와 조회 시각이 최종 판단에 남았다. |
| 파이트와 개인 지시 | 택시와 대중교통이 각각 필수일 때 첫 판단은 미합의였다. 방장이 자신의 에이전트에게 택시 조건을 양보한 뒤 두 번째 판단에서 대중교통에 합의했다. 같은 지시는 한 번만 접수됐고, 다른 참가자의 화면에는 원문이 보이지 않았다. 미입장자의 지시는 403, 마감 후 새 지시는 409를 받았다. |
| 최종 저장 | 네 세션이 동일한 여행안을 읽었다. 같은 SQLite 파일로 앱을 새로 구성한 뒤 기존 쿠키를 사용해도 동일한 결과를 읽었다. |

앱 커밋은 `028ee2e`, 실행 전후 `travel_app/` 트리는 모두 `01683c6c539183d6332416d3f2ecc2b152dae24a`였다. [통합 시험 코드](../../tests/test_group_travel.py)

로컬 시험 환경은 Windows, Python 3.11.17, Flask 3.1.1, LangGraph 1.2.15, SQLite 3.53.4였다. Flask HTTP 테스트 클라이언트, 실제 백그라운드 실행기와 컴파일된 그래프를 연결했다. 시간 제약은 지시 반영을 확인한 뒤 시험 시계를 46초 앞으로 옮겨 검증했다. Gemini 생성과 Google 검색의 외부 응답만 고정된 시험 데이터로 공급했다. 실제 모델·검색과 인터넷 지연, Render 가동 상태는 배포 환경에서 별도로 확인할 항목이다.

저장소 루트에서 의존성이 설치된 환경으로 실행한다.

```shell
python -m unittest discover -s tests -v
python -c "import unittest,sys; suite=unittest.TestSuite(unittest.defaultTestLoader.discover('tests', pattern='test_group_travel.py') for _ in range(10)); sys.exit(not unittest.TextTestRunner().run(suite).wasSuccessful())"
```
