# TRIP-02 · 판사 에이전트 검증

2026-11-27, 제품 커밋 `7ceea9f5aa4ae5c7cacb83f0720373e406ccb732`에서 전체 회귀 시험 23개가 통과했다. 실제 Chrome의 모바일·데스크톱 세션에서도 즉시 합의와 파이터 모드 후 합의 양쪽에서 최종 여행안을 확인했다. 판정 기준은 `8eb4906`에서 출발한 J1~J4(요구사항 Git blob `2f450e2209df26ad5ef6f6ef649d9e8c4338c029`)와 [화면 흐름](../design/travel-flow.md), [ADR-003](../adr/travel.md#adr-003--두-모드의-판단과-최종-결정을-한-판사-에이전트에-맡긴다)이다.

| J2 · 변경 권한과 근거 | 상대 상한 60만 원, 방장 고정 상한 40만 원, 수신 번호 불일치, 미승인 통화 변경을 각각 시도한다. 판사에게는 근거 없는 항공 합의도 반환한다. | 상대 상한은 60만 원, 방장 고정값은 40만 원이었다. 번호가 다른 상향 제안과 엔화 제안은 모두 기존 50만 원으로 남았다. 마지막 판사 입력의 남은 횟수는 0이었고 필수 교통 충돌은 미해결, 운임 근거가 없는 항공은 확인 필요였다. 고정·알 수 없는 항목으로 온 지시가 개인의 다른 필수 조건을 바꾸지 않았다. |
| J2·J3 · 두 번의 토론과 말투 | 같은 조건에서 간결한 판사와 다정한 판사가 각각 두 토론을 진행한다. 두 개인은 끝까지 양보하지 않는다. | 두 판사의 공개 인사는 달랐다. 최초·첫 토론 후·마지막 토론 후의 판단 입력 전체와 최종 결정은 두 방에서 같았다. 남은 횟수는 2→1→0이었고 매번 이전 회차들만 이력으로 전달됐다. 마지막 여행안에서 부산은 고정, 현지 이동수단은 값이 없는 미해결이었다. |
| J4 · 옛 방과 재접속 | 과거 프리셋 문자열과 8개 이벤트가 섞인 완료 방을 두 세션에서 다시 연다. 별도 진행 중 방은 예산 변경을 옛 제안 형식으로 저장하고 앱을 다시 만든다. | 과거 진행자의 단계·파이터 공지·판단·오류·최종 게시 화자가 판사로 보였다. 공지 안의 시스템 문구만 바뀌었고 ID·시각·순서, `중재자`라는 참가자 이름·개인 발언·자유 말버릇·저장 원문이 보존됐다. 옛 `floor`에서 재개한 첫 판단은 이전 이력과 좌석별 의견을 읽어 기존 70만 원 상한으로 종료했다. `mediator` 필드와 `MEDIATOR_MODEL` 설정 키도 유효했다. |

수정 전 제품 `8698fc9`에서는 고정 예산 지시가 다른 사람과 충돌하는 자기 교통 필수 조건을 선호로 바꾸어 잘못 합의했다. 같은 시험에서 수정 후에는 양쪽 필수 조건과 미해결 판정이 남았다. 발언 모델이 접수 번호 1의 항목을 두 번 잘못 반환한 경우도 검증했다. 두 응답 모두 발언·처리 완료를 기록하지 않았고 세 번째 응답에서 예산을 반영한 공개 발언 한 건을 저장했다. [판사 API 시험](../../tests/test_judge.py)

이후 독립 시험 리뷰에서 음식 변경과 같은 발언 안의 검색이 앞선 조건을 사용한 사례를 발견했다. 새 시험의 세 입력을 옛 제품 `7ebea19`의 `travel_app/`만 푼 임시 디렉터리에서 실행했을 때 모두 실패했다. 재검색 두 경우 모두 실제 요청이 ‘삼겹살 → 삼겹살’이었고, 재검색이 없을 때 옛 인용은 판사 입력에 `observed`로 남았다. 수정본에서는 세 입력 모두 위 표의 판정을 받았다. 해당 항목만 재현하려면 전체 시험 명령 끝에 `-p test_judge.py -k changed_dish`를 추가한다.

## Chrome에서 확인한 J3·J4

1. 독립된 두 세션(360×850, 1100×850)에 동작 줄이기를 설정한다. 방장 브라우저의 `sessionStorage`에 과거 `trip:create-draft` 형식의 닉네임 `초안 방장`과 `mediator` 문자열 `간결한 진행자`를 넣는다. 홈의 ‘사용법 보기’에서 판사 에이전트와 파이터 모드 안내를 읽고 닫는다.
2. ‘여행방 만들기’를 열면 과거 닉네임과 ‘간결한 판사’가 선택돼 있고 프리셋 값은 `간결한 진행자`였다. 접근성 이름 ‘공격성’으로 슬라이더에 초점을 두고 오른쪽 방향키를 눌러 5에서 6으로 올렸다. 이전 `2e94088`의 접근성 트리에서는 이 슬라이더의 이름이 비어 있었다.
3. 방을 만든 뒤 초대 URL로 입장한다. 두 세션에서 현지 이동수단 ‘직접 입력’과 필수 등급을 택해 ‘제출 내용 확인’ → ‘준비 완료’를 누른다. 두 사람이 대중교통을 선택하면 양쪽에서 조율 모드를 거쳐 판사의 최종 합의가 표시됐다.
4. 새 방에서는 방장이 택시, 참가자가 대중교통을 필수로 제출한다. 양쪽 파이터 배너의 ‘대화 보기’에서 Enter를 누르면 공개 대화로 초점이 이동했다. 방장이 자기 에이전트에게 대중교통으로 양보하라고 보낸 뒤 전달 완료를 확인하고 서버 시계를 50초 진행했다.
5. 두 경우 모두 새로고침한 양쪽 화면에서 현지 이동수단은 ‘대중교통·합의’였다. 이력에는 해당 모드의 판사 판단이, 공개 대화의 마지막 발언에는 ‘판사 에이전트’가 표시됐다. 공개 채팅에 지시 표식이 없었고 가로 넘침과 JavaScript 예외도 없었다.

브라우저 시험은 실제 루프백 HTTP와 SQLite를 사용했다. 입력은 브라우저 양식으로 제출하고, 저장된 단계 사이에 컴파일된 LangGraph를 호출했다. Chrome 157.0.8103.51, Playwright 1.65.2에서 로컬 보조 스크립트 `.\.venv\Scripts\python.exe -u .venv/trip02-snapshot/ui_check.py`를 사용했다(스크립트 SHA-256 `e06387e5aa76f3c46495e9667016d92268f694a8d868f6d4e3a78dabde2f859f`). 다른 체크아웃에서는 위 절차와 [외부 응답·시계 대역](../../tests/test_group_travel.py)으로 재현할 수 있다.

## 실행 기준과 재현

Windows 빌드 26200, Python 3.11.9, Flask 3.1.1, LangGraph 1.2.15, SQLite 3.45.1을 사용했다. 실행 당시 `travel_app/`은 제품 커밋과 일치했고 트리는 `53e02bebe1d99621f3c3f45228215481b20b8d09`였다. 실행한 `tests/` 트리는 `7a05cddcd4855b45085d1ceba07b9f28c6b986e6`이며 `test_judge.py`의 blob은 `c0212a864bed7c2b9088b28f4c536bf0ae7e35f1`, `test_room_recovery.py`의 blob은 `4177594e0baaa7d0f37311fbeb17620b9d66ad91`이다.

```powershell
$env:TRAVEL_TEST_TRANSPORT = 'wsgi'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -c "import sys, unittest; suite=unittest.TestSuite(unittest.defaultTestLoader.discover('tests', pattern='test_judge.py') for _ in range(3)); sys.exit(not unittest.TextTestRunner().run(suite).wasSuccessful())"
Remove-Item Env:TRAVEL_TEST_TRANSPORT
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

최종 제품에서 WSGI 전체 23/23개가 4.912초, 새 방을 사용한 판사 전용 세 차례 반복에서 24/24개가 8.476초에 통과했다. 루프백 소켓을 허용해 실행한 기본 전송 방식에서도 23/23개가 7.053초에 통과했다. 위 Chrome 시나리오 두 개도 최종 제품으로 다시 실행해 통과했다. 건너뛴 자동 시험은 0개였다. Gemini의 생성과 Google 검색 응답은 고정 대역을 썼다. 이번 검증에서는 외부 모델 호출, Render·PostgreSQL 배포, 실제 화면 낭독기 및 오디오 재생을 실행하지 않았다.

앞선 제품 `7ebea193e75fdad90e00a5c9aef8856076c1d886`의 런타임 트리는 `d2bdf9d1e3b56dd5bd4d1e7bb08e397df8d4175c`, 당시 시험 트리는 `96e258cd2f42676f9a6895dbfc524c6a4185534d`였다. 음식 변경과 재검색을 함께 다루는 시험을 추가하기 전에는 WSGI 22/22개(4.095초), 루프백 22/22개(5.238초), 판사 전용 반복 21/21개(7.255초)가 통과했다.
