# SEM-01 · 여행 검색과 활동 합의의 의미 판정 검증

2026-11-27. 기준 커밋 `213567c5046e85bc906b49f8f2b692b306bcd2c5`의 작업 트리에서 Windows, Python 3.11.9, LangGraph 1.2.15, Flask 3.1.1과 SQLite로 검증했다. [구현 계약](../design/travel-implementation.md#sem-01--모델의-의미-판정) · [설계 결정 ADR-006](../adr/travel.md) · [앞선 역할별 호출 검증](agent-prompts.md)

## 수정 전 재현

기존 WSGI 회귀 시험 32개는 모두 통과했다. 그런데 실제 검색 처리기에 ‘채식 라멘’ 요청과 일반 라멘 판매 인용을 보내면 확인됨이었다. 채식 라멘 판매 인용에 ‘주차장은 없습니다’를 붙이면 확인 필요로 바뀌었다. 같은 세금 포함 운임과 같은 장소를 다르게 표현한 경우도 확인 필요가 됐다. 기존 판정 함수는 두 필수 활동을 ‘그리고’로 연결하면 합의, ‘후’ 또는 ‘또는’으로 연결하면 모두 미합의로 처리했다.

## 수정 후 확인한 동작

| 대상 | 입력과 관찰 결과 |
| --- | --- |
| 식당·장소·운임 | 같은 지점 일반 메뉴, 다른 지점의 제공, 향후 출시, 현행 채식 메뉴와 주차장 부재를 각각 담은 네 구간이 요청 조건과 함께 한 차례 검토에 들어갔다. 모델 대역이 마지막 구간만 승인하자, 확인 표시는 그 링크에만 붙었다. 제안자와 판사에 전달되는 데이터에도 네 번째 구간이 남았다. 승인된 원문의 장소명과 같은 장소만 일정에 반영됐다. 자연어로 적은 ‘세금이 포함된 가격’도 승인 후 원본에 기재된 금액을 게시했다. 공항·날짜·시간대·통화가 틀린 가격은 검토 대상에서 제외됐다. [검색·일정](../../tests/test_semantic_review.py) · [운임 구조 검사](../../tests/test_flight_evidence.py) |
| 단일 출처와 검토 실패 | 복수 출처만 붙은 구간, 범위 밖 출처 번호, 검토 호출 실패와 잘못된 응답에서는 확인 표시가 생기지 않았다. 첫 구현에서 같은 문장의 복수 출처 구간이 단일 출처 구간보다 먼저 나오면 단일 인용까지 버리는 오류를 재현했다. 수정 후에는 두 순서 모두 원래 단일 출처만 인정했고, 검토할 수 없는 인용 여섯 개 뒤에 있는 유효한 인용도 남았다. [인용 경계 시험](../../tests/test_semantic_review.py) |
| 필수 활동 | ‘관람 후 산책’에 대한 두 요구의 승인 결과를 받아 합의했고, 두 활동 중 하나만 투표로 결정하는 안은 미합의였다. 요구 누락·중복, 존재하지 않는 일정 번호, 불리언을 정수 번호로 쓰는 응답, 검토 실패도 미합의였다. 동백공원 산책 요구에는 검증한 날짜·장소·교통수단·행 번호가 함께 전달됐다. 날짜 밖 행과 미확인 장소의 활동은 판정 근거가 되지 않았다. 방 API를 통과한 4인 시나리오에서도 두 사람의 필수 활동을 서로 다른 날짜에 배정한 결과를 확인했다. [활동 검토 시험](../../tests/test_semantic_review.py) · [4인 여행방](../../tests/test_group_travel.py) |
| 저장과 공개 | 이전 버전에서 확인됨이던 운임과 식당은 재접속해도 확인 필요였고 미검증 운임 금액은 공개되지 않았다. 같은 방의 새 검증 기록을 가진 운임·메뉴는 확인됨으로 유지됐다. 검토 후 인용문이나 URL 또는 조회 조건을 교체하면 기존 판정은 효력을 잃었다. 공개 응답에 내부 검토 필드는 없었다. [이전 방의 API 조회](../../tests/test_quote_and_branch_conditions.py) |
| 발언 | ‘최저가를 확인해 볼게요’와 ‘이 표가 최저가라고 보장해요’가 모두 의미 검토에 도달했다. 가격 조회 의향을 승인한 경우 생성한 말을 전달했고, 새 보장을 거절한 경우 원래 발언을 전달했다. 검증되지 않은 금액·사적인 지시·페르소나의 금지 인용을 막는 회귀 시험도 실행했다. [공개 발언 시험](../../tests/test_semantic_review.py) · [페르소나 시험](../../tests/test_persona.py) |
| 혼합 근거의 화면 | Chrome 157.0.8103.51의 360px 창에서 실제 결과 화면 함수를 실행했다. 혼합 카드의 두 링크에서 ‘조건 확인’과 ‘확인 필요’가 각각 표시됐고, 두 URL과 Tab 이동 순서가 일치했다. 모두 확인 또는 모두 미확인인 카드에서는 제목을 반복하지 않았고 가로 스크롤이 없었다. |

## 의미 판정의 별도 점검

기대 정답을 전달하지 않은 별도 Codex 모델에 제품의 검색·활동 검토 지시문과 합성 입력을 제공했다. JSON 응답을 실제 검색·판정 함수에 재생해 전달한 지시문과 데이터가 일치하는지도 확인했다. 솔빛역점의 채식 만두 재료와 육수 사용 여부를 뒷받침하는 문장은 승인했고, 다음 분기에 채식 메뉴를 검토한다는 문장은 거절했다. 대전에 있는 전시관과 대전에서 출발해 공주에서 방문하는 전시관도 구분했다. 공예 전시를 둘러본 뒤 호숫가를 걷는 안은 합의, 두 활동 중 하나를 투표로 정하는 안은 미합의였다.

자동 회귀 시험은 Gemini 요청 직렬화, 그래프·DB 처리와 화면에 나타나는 결과를 검증하며, 외부 생성·검색 응답은 시험 대역에서 제공했다. 별도 모델 점검은 네 합성 입력에 한정했다. 실행 환경에 Gemini API 키가 없어 Google 검색이나 실제 Gemini 서비스의 정확도·지연시간·비용은 측정하지 않았다.

## 재현

```powershell
$env:TRAVEL_TEST_TRANSPORT = "wsgi"
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -p test_semantic_review.py -v
.\.venv\Scripts\python.exe -B -m unittest discover -s tests
```

최종 코드 재검토 후 집중 시험 7개가 0.003초에, WSGI 전체 39개가 5.460초에 통과했다. 같은 최종 코드에서 `TRAVEL_TEST_TRANSPORT`를 설정하지 않은 별도 전체 실행도 39개 모두 통과했다(7.389초). 기본 실행에서는 방 API 시나리오가 로컬 HTTP 서버를 경유한다. 생략하거나 건너뛴 회귀 시험은 없다.

두 참가자의 API 흐름에서는 실제 Gemini 요청 본문을 구성한 뒤 네트워크 응답만 대체했다. 인용 검토 요청은 개인 모델, 날짜별 활동 검토 요청은 판사 모델의 JSON 호출로 전달됐고, 인용 검토 자체는 Google 검색 도구를 다시 호출하지 않았다. 두 검토 요청 모두 개인 지시 원문과 페르소나 설정을 포함하지 않았다. [요청 본문 시험](../../tests/test_agent_prompts.py)
