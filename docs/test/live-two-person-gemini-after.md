실제 자유 생성 표현을 채택한 발언은 서윤 0/2·민재 1/2·판사 3/3, 합계 4/7이었다. 나머지 세 번은 기본문이었다. 참가자의 생성·재작성 요청에서 값을 `{value}`로 감췄어도 서윤이 요청한 존댓말 문체를 살린 새 발언이 두 번 모두 나오지 않았다. 이 결과로 문체 복구를 추가 검증했다.

이 방에서는 접근성 값이 생성되지 않아 “미정 · 확인 필요”였다. 참가자가 제출하지 않은 “국립중앙박물관 접근이 용이한 용산구 인근 숙소”는 “AI 제안”으로 표시됐다. 방문지 근거는 0/6이었다. 12월 5일에는 “국립중앙박물관 전시 관람 · 후보 · 확인 필요”와 “서울 · 세부 장소 확인 필요”, 6일에는 “한강 산책 · 후보 · 확인 필요”가 표시됐다. 양일 이동은 대중교통이었다. 숙소 충돌은 없었고 실제 토론은 현지 이동 1회였다. 판사 전송 2회는 6.07초·5.78초(합계 11.85초), 시간 초과와 수동 재시도는 0회였다.

## 세 번째 재생 · 최종판

21시 32분 32초(KST)에 시작했다. 원본에서 입력 JSON의 다섯 키와 그 안의 모든 값이 기준 방과 같은지 확인했다. 두 참가자가 받은 공개 발언 11건, 이력 2건, 최종안 12항목을 직접 비교했다. 두 Chrome 화면의 결정 목록·날짜별 일정·가로 넘침 여부도 일치했다. 키보드 Enter로 세부 항목을 펼쳤다. 민재는 38.27초에 지시 1번을 보냈고 처리가 끝났다. 서윤의 지시 목록은 비어 있었고 판사 요청·공개 기록에 원문이 없었다.

서윤의 2건에는 모두 요청한 격식체가 반영됐으나 공개문이 반복됐다. 자유 생성한 서윤 문장을 그대로 게시한 건수는 0건이다. 민재는 자유 발화 1건·모델 선택 문체 1건, 판사는 자유 발화 3건이었다. 잘못된 후보를 기각한 뒤에도 참가자의 말높이는 살렸지만, 서윤이 요청한 문장 호흡이나 어휘 전체를 되살렸다고 볼 근거는 없다.

### 최종 결정과 일정

- **참가자가 제출·수용한 값** · 1차 판사 요청에서 서윤은 대중교통 필수, 민재는 택시 필수였다. 2차 요청에서 민재는 대중교통 선호로 바뀌었고 `participant_fields`에 `local_transport`가 있었다. 공개 최종안에서 대중교통과 35만 원은 합의, 서울·대전·여행 날짜·기차는 사전 확정이었다.
- **접근성과 숙소** · 최종판은 두 항목의 새 후보를 제시하지 않았고 두 항목 모두 “확인 필요 · 미정”이었다. 첫 수정판에는 실제 접근성 추천이 나와 AI 제안임을 확인했다. 최종판 대역 방에서는 판사가 “휠체어 리프트”를 임의로 합의 처리해도 `suggested/agent`로 표시됐다. 숙소 불일치와 근거 부족의 동시 표시는 아래의 두 세션 회귀 시험에서 재현했다.
- **날짜별 부분 확인** · 공개 근거 중 장소와 서울 소재를 함께 입증한 인용은 0/4였다. Chrome에서 12월 5일 “국립중앙박물관 전시 관람 · 후보 · 확인 필요”, 6일 “한강 산책 · 후보 · 확인 필요”를 확인했다. 양일 모두 서울·대중교통, 첫날 장소에는 “세부 장소 확인 필요”가 붙었다. 한강이 확인돼 일정에 반영되는 경우는 독립 근거가 있는 회귀 입력으로 확인했다.
- **여전히 필요한 조율** · 첫 판사가 35만·50만 원이라는 같은 통화의 예산 상한을 현지 이동과 함께 분쟁으로 지정했다. 첫 이력에는 35만 원 값이 “미해결”로 기록되어 예산 토론이 열렸다. 두 번째 판단에서 35만 원으로 합의했으며 실제 교통 양보도 반영됐다. 지출 한도가 다를 때 모델이 예산을 쟁점으로 올릴 수 있다는 점은 남아 있다.

### 과거 발언을 다시 검토한 실모델 탐침

실제 의미 검토 응답을 다시 읽고 서버의 값 표식 검사와 의미 검사를 각각 실행했다. 아래의 “통과”는 해당 검사를 통과했다는 뜻이다. 이 탐침은 방의 게시 이벤트를 만들지 않았다.

발언 생성 보완판과 최종판에서 원래의 세 탐침을 실제 모델로 각각 반복했다. 양쪽 모두 예산 조건·효율 최상급을 의미 단계에서 거부했고, 반말 양보는 허용했다(각 3/3). 최종판 원본 검토 응답에 서버 검사를 다시 적용한 결과도 거부·거부·허용이었다. 같은 최상급 후보가 첫 수정판에서 의미 단독 검사를 통과한 기록은 남겨 두었다.

### 고정 응답으로 확인한 경계

Windows, Python 3.11.9, Flask 3.1.1, LangGraph 1.2.15, SQLite 3.45.1에서 첫 수정판 전체 WSGI 63/63(6.831초), 루프백 HTTP 63/63(9.093초), 아래 집중 시험 12/12(1.075초), 건너뜀 0건. 루프백은 샌드박스의 Windows 오류 10013을 확인한 뒤 허용된 환경에서 다시 실행했다. 로컬 시험에는 프로세스 전용 가짜 키를 지정했다.

발언 생성 보완판에서 다시 실행한 전체 회귀 시험은 WSGI 67/67(6.851초), 루프백 HTTP 67/67(9.728초)였고 건너뜀은 0건이었다. 양보·제안 오분류, 값 중복, 생성·수정 요청에서 실제 값 감추기, 날짜별 일부 검증, 구형 방 재조회를 포함하는 집중 시험은 25/25(1.225초)였다. 제3의 음식 제안과 구형 실측 방 복원 시험도 보완판에서 다시 통과했다.

최종판은 WSGI 69/69(7.845초), 루프백 HTTP 69/69(10.141초), 집중 시험 30/30(1.964초), 건너뜀 0건이었다. 같은 구형 방을 재조회하고 제3의 값을 제출하는 시험도 다시 통과했다. 별도 구성한 모델 대역에서 매번 “효율성을 보장해.”를 발언 후보에 추가하고 의미 검토를 실패시켰다. 네 행동(제안·양보·대안 검토·근거 확인) × 말높이 세 종류 × 도입 세 종류의 36/36개에서 값은 한 번만 나오고 지목한 행동과 어미를 지켰다. 등록되지 않은 말투, 이상한 자료형, 임의의 도입 문구 등 7/7개는 기본문이었다. 서버 기준문과 다른 문장과 판사 발언도 2/2개 기본문이었다. 45개 모두 추가한 보장 문구가 게시되지 않았다.

- 출처 없는 추천, 다른 좌석의 동의, 자율 양보, 원본 인용·값·통화 불일치, 지시 검토 장애 후 한 번만 게시하는 경로를 확인했다. 별도 WSGI 방에서 서로 다른 “칼국수”, “해물탕” 선호에 판사가 “비건 뷔페”를 합의로 반환하게 했다. 두 세션의 최종 음식 상태는 `verify`, 출처는 `agent`였다. 아무도 요구하지 않은 “휠체어 리프트”는 `suggested/agent`였다. [2인 회귀 시험](../../tests/test_pair_intent.py)
- 양보 대신 제안으로 행동이 바뀌거나, 행동 근거가 값만 인용하거나, 후보의 새 문장이 정렬된 인용에서 빠지면 기본문을 게시했다. 새 숫자와 비공개 문구도 공개에서 제외했다. [발언 회귀 시험](../../tests/test_persona.py)
- “강남” 대 “종로” 필수와 숙소 근거 부족을 함께 입력하면 두 세션의 이력 및 최종값은 `unresolved/null`이고 별도 사유는 “후보 숙소의 조건을 확인해야 해요.”였다. 박물관에 근거를 주지 않고 한강에 독립적인 근거를 준 시험에서는 박물관만 후보로 남고 한강 산책은 `planned`였다. [충돌·확인 사유](../../tests/test_pair_intent.py) · [날짜별 부분 검증](../../tests/test_semantic_review.py)
- 이전 실측의 `events`, `history`, `result`를 완료한 별도 시험방에 복원했다. 두 참가자의 API에서 과거 발언 16건, 판정 3건, 결정 12항목, 날짜 2건의 공개 값이 과거 JSON과 같았고 재조회 후에도 유지됐다. 미입장 세션에는 결과가 없었다. 이전 방의 새 출처 표기를 소급해 추정하지 않는다. [이전 형식 회귀 시험](../../tests/test_judge.py)
