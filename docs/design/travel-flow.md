# 함께 정하는 여행

TRIP-01 · 화면 및 상호작용 설계 · 기준 커밋 `330f872`

## 여행방에서 결과까지

| 화면 | 사용자가 하는 일 | 화면이 보여 주는 결과 |
| --- | --- | --- |
| 처음 화면 | 인사를 읽고 `여행방 만들기` 또는 `사용법`을 누른다. | 짧은 흑백 여행 애니메이션과 함께 두 동작이 즉시 열린다. 사용법을 닫으면 누르던 위치로 돌아간다. |
| 방장 설정 | 방의 인원수를 정하고 이미 확정된 여행 정보를 항목별로 입력한다. `방 중재자의 성격과 말투`에서 공통 진행자의 성향을 정한다. | 여행 지역, 날짜, 1인당 최대 예산, 항공편 일정, 현지 이동수단, 숙소 등에서 직접 정한 값만 `확정된 조건`에 모인다. |
| 초대와 입장 | 방장은 링크를 복사하거나 링크 전체를 선택해 공유한다. 초대받은 사람은 확정된 여행 정보와 현재 인원을 확인하고 이름을 정해 입장한다. | 방장을 포함한 실제 입장자가 대기 명단에 나타난다. 이미 입장한 브라우저는 자신의 현재 단계로 돌아간다. |
| 내 여행 조건 | 방장과 참가자 모두 남은 항목을 맡기거나 자신의 희망 조건을 입력한다. 추가 요청을 남기고 `내 에이전트의 성격과 말투`를 정한다. | 방장이 확정한 항목은 옅은 회색 배경에 자물쇠와 `방장이 확정함`을 붙인다. 값을 읽을 수 있고 수정 동작은 제공하지 않는다. 전 항목을 맡긴 사람도 다음 단계로 갈 수 있다. |
| 제출과 대기 | 요약에서 공통 조건과 내 설정을 확인한 뒤 `준비 완료`를 누른다. | 화면에 `입장 2/3명`과 `준비 1/3명`처럼 다른 수치를 표시한다. 방장까지 포함해 정해진 인원이 전부 제출하면 협상이 한 번 시작된다. |
| 협상 | 에이전트들의 제안, 중재자의 조정, 합의한 항목을 읽는다. | 진행 상태를 `일반 협상`, `파이트 모드`, `최종 결정`으로 구분한다. 상태가 바뀌면 이유와 현재 논의 항목을 글로 알린다. |
| 에이전트 단체 채팅 | 파이트 모드 알림의 `대화 보기`에서 각 에이전트의 대화를 보고, 필요하면 `내 에이전트에게만 지시`를 연다. | 공개 대화에는 에이전트 이름과 발언을 순서대로 표시한다. 개인 지시는 보내는 대상의 이름을 명시하고 별도 입력창, 기록, 전송 상태를 쓴다. |
| 최종 여행안 | 어떤 항목이 어떻게 정해졌는지 확인한다. | 먼저 핵심 여행 일정과 예산을 보여주고, 날짜별 장소·이동·활동 등 실제 결정 내용을 펼쳐 본다. 사전 확정 항목과 협상에서 결정한 항목의 근거를 구별한다. 미정인 값은 `미정`으로 표시한다. |

## 여행 조건 입력

항목마다 기본 선택은 `에이전트에게 맡기기`다. `직접 입력`을 선택한 항목에만 입력창을 펼친다. 뒤로 갔다 돌아오거나 일시적으로 맡기기로 바꿔도 작성 중인 값은 복구할 수 있다. 맡기기로 제출한 항목에는 이전에 입력한 값을 보내지 않는다.

| 항목 | 직접 정할 때의 동작 |
| --- | --- |
| 여행 날짜 | `시작일`과 `종료일`을 지정한다. 날짜가 뒤집히면 종료일 옆에 수정 안내를 표시한다. |
| 1인당 최대 예산 | 수직선 형태의 슬라이더에 있는 손잡이 하나를 움직여 한 사람이 쓸 수 있는 최대 금액을 정한다. 현재 금액과 단위를 표시한다. 정확한 금액을 숫자로 입력하면 슬라이더도 그 값에 맞춰 움직인다. 요약에는 `1인당 최대 55만 원`처럼 한 금액을 표시한다. |
| 항공편 일정 | 가는 편과 오는 편을 구별해 날짜·시간과 알고 있는 노선 또는 편명을 입력할 수 있다. 편명을 모르는 참가자도 `가는 편은 첫날 오전, 오는 편은 마지막 날 저녁`처럼 원하는 시간대를 전할 수 있다. |
| 현지 이동수단 | `택시`, `대중교통`, `렌터카`를 선택지에 명시한다. 항공편을 정했어도 현지 이동수단은 따로 맡기거나 선택할 수 있다. |

## 중재자와 개인 에이전트의 성격

`방 중재자의 성격과 말투`와 `내 에이전트의 성격과 말투`는 각각 **공격성, 예의, MZ 감성** 세 가지 슬라이더와 `원하는 말투` 자유입력란을 제공한다. 각 슬라이더에는 항목명, 양 끝의 `0`과 `10`, 현재 정숫값을 표시한다. 손가락으로 끌거나 키보드 방향키로 한 단계씩 바꿀 수 있다. 방장이 자신의 에이전트를 설정해도 앞에서 정한 중재자의 값은 보존한다. 다른 참가자도 각자의 에이전트를 독립적으로 설정한다.

파이트 모드에서 중재자가 말을 할 때는 중재자의 세 수치와 자유입력 지시를 함께 사용한다. 개인 에이전트의 발언은 해당 참가자가 정한 수치와 말투를 따른다. 예를 들어 같은 교통비 쟁점을 두고 중재자에게 `두 의견을 정중하게 한 문장으로 요약해 줘`, 내 에이전트에게 `요점을 먼저 반말로 말해 줘`라고 입력했다면 공개 대화에서 각 발화자의 표현에 그 차이가 드러나야 한다.

## 알림과 대화

- 파이트 모드가 시작되면 방에 머무는 참가자에게 `파이트 모드가 시작됐어요`와 `대화 보기` 버튼이 있는 눈에 띄는 배너를 한 번 띄운다. 보조기기도 같은 내용을 한 번 읽는다. 화면을 떠났다가 돌아온 사람도 대화 입구를 찾을 수 있다. 기기 정책과 사용자의 설정이 허용하는 경우 소리나 진동을 더할 수 있다. 무음이거나 동작 줄이기를 켜도 배너와 버튼은 그대로 읽고 누를 수 있어야 한다.
- 공개 발언에는 말한 에이전트 또는 중재자, 논의 항목과 새 발언 여부가 나타난다. 이전 발언을 읽는 중에는 읽던 위치를 유지하고 `새 발언 보기`를 제공한다.
- 개인 지시는 전송에 성공하면 `내 에이전트에게 전달됐어요`로 바뀐다. 에이전트는 다음 적용 가능한 발언이나 판단에서 이를 사용한다. 다른 사람의 화면에는 개인 지시 원문이나 보낸 이의 사적인 설명을 표시하지 않는다. 협상이 끝난 뒤 도착한 지시에는 마감 안내를 표시한다.
- 입력 오류는 해당 항목 옆에 수정 방법을 표시한다. 전송 실패 시 초안을 보존하여 다시 보낼 수 있다. 입장 불가 사유를 구분하며, 끊겼다가 연결되면 방의 상태·대화·결과를 복원한다. 대기와 협상 화면에서 중복 터치나 새로고침으로 제출과 발언이 중복되지 않아야 한다.

## 화면 및 접근성 확인

참고 이미지에서 흰 바탕, 옅은 회색 구분선, 짙은 본문과 주 버튼, 왼쪽 정렬된 제목, 넉넉한 여백을 가져온다. 모바일은 한 화면에 한 단계를 보여주고, 넓은 화면에서는 읽기 폭을 유지한다. 긴 입력 화면이나 채팅에서 하단 버튼이 마지막 입력칸 또는 메시지를 가리지 않아야 한다.

| 확인 장면 | 관찰할 결과 |
| --- | --- |
| 두 브라우저에서 방장과 초대받은 사람으로 입장 | 서로의 공개 정보는 같고 개인 설정과 개인 지시는 작성자에게만 보인다. 모두 맡기기와 일부 직접 입력 양쪽에서 제출할 수 있다. |
| 방장이 슬라이더로 1인당 최대 예산을 50만 원으로 정한 뒤 55만 원을 직접 입력하고, 참가자가 항공편 시간대와 현지 대중교통을 선택 | 슬라이더의 금액도 55만 원으로 바뀐다. 참가자는 회색 행의 자물쇠·확정 표시와 `1인당 최대 55만 원`을 읽을 수 있다. 항공편 일정과 현지 이동수단의 선택이 요약에 별도로 남는다. |
| 방장이 중재자와 자기 에이전트의 세 슬라이더를 서로 다른 값으로 조절하고 말투 지시도 다르게 제출 | 양 끝값 0·10과 중간값을 터치와 키보드로 선택할 수 있다. 파이트 모드에 등장한 두 화자의 발언은 각자의 수치와 자유입력 지시를 반영한다. |
| 마지막 참가자가 준비를 연속해서 누름 | 두 화면이 한 협상으로 진입하고 인원과 준비 수가 일치한다. |
| 무음 상태에서 파이트 모드 진입 후 같은 화면 새로고침 | 상태 전환이 배너로 즉시 드러나고 `대화 보기`가 해당 방의 대화를 연다. 같은 사건을 다시 알리지 않아도 대화로 들어갈 수 있다. |
| 파이트 모드 중 한 사람이 개인 제안을 전달 | 공개 대화와 수신자에게만 보내는 입력이 구분된다. 받은 에이전트의 후속 발언이나 판단에서 변화가 관찰된다. |
| 대화 도중 연결이 끊기거나 최종 여행안을 다시 열기 | 복구한 방의 단계와 발언 순서가 맞고, 참여자들이 같은 최종 결정을 확인한다. |
| 360px 화면, 키보드 이동, 동작 줄이기 설정 | 가로 스크롤 없이 조작할 수 있고, 초점과 입력 이름·단위가 명확하다. 화면 갱신이 초점을 빼앗지 않는다. 애니메이션은 정지 화면으로 대체한다. |
| 보조기기로 알림과 상태 확인 | 새 단계, 준비 완료, 새 발언, 전송 오류를 글자로 식별하고 알림의 동작에 키보드로 접근한다. 터치 대상은 44px 이상으로 하고 바탕과 본문은 대비 4.5 대 1 이상을 확보한다. |
