## 여행방에서 결과까지

| 화면 | 사용자가 하는 일 | 화면이 보여 주는 결과 |
| --- | --- | --- |
| 처음 화면 | 인사를 읽고 `여행방 만들기` 또는 `사용법`을 누른다. | 짧은 흑백 여행 애니메이션과 함께 두 동작이 즉시 열린다. 사용법을 닫으면 누르던 위치로 돌아간다. |
| 방장 설정 | 처음 방문한 사람도 닉네임과 인원을 정하고, 확정된 여행 정보와 판사 에이전트의 성격·말투를 설정해 방을 만든다. | 팀 개설 코드 없이 방장이 첫 참가자로 입장하고 이 방의 초대 링크를 받는다. 직접 정한 항목만 `확정된 조건`에 모인다. |
| 초대 링크 공유 | 생성 직후 열린 공유 화면에서 방장이 초대 링크를 복사해 동행에게 보낸다. | 방장은 복사 전후 언제든 자기 여행 조건 입력으로 넘어갈 수 있다. |
| 초대받은 사람의 입장 | 받은 링크를 열고 확정된 여행 정보와 현재 인원을 확인한 다음 닉네임을 정해 입장한다. | 방장을 포함한 실제 입장자가 대기 명단에 나타난다. 이미 입장한 브라우저는 자신의 현재 단계로 돌아간다. |
| 내 여행 조건 | 방장과 참가자 모두 남은 항목을 맡기거나 자신의 희망 조건을 입력한다. 추가 요청을 남기고 `내 에이전트의 성격과 말투`를 정한다. | 방장이 확정한 항목은 옅은 회색 배경에 자물쇠와 `방장이 확정함`을 붙인다. 값을 읽을 수 있고 수정 동작은 제공하지 않는다. 전 항목을 맡긴 사람도 다음 단계로 갈 수 있다. |
| 제출과 대기 | 요약에서 공통 조건과 내 설정을 확인한 뒤 `준비 완료`를 누른다. | 화면에 `입장 2/3명`과 `준비 1/3명`처럼 다른 수치를 표시한다. 방장까지 포함해 정해진 인원이 전부 제출하면 협상이 한 번 시작된다. |
| 조율 모드 | 각 개인 에이전트의 제안과 판사 에이전트의 판단을 읽는다. | 판사는 전원의 제안과 근거를 종합한다. 의견이 모이면 최종 여행안을 확정하고, 충돌이 남으면 논의할 항목을 알리고 파이터 모드를 연다. |
| 파이터 모드 | 알림의 `대화 보기`에서 판사가 제시한 쟁점과 각 에이전트의 발언을 읽는다. 필요하면 `내 에이전트에게만 지시`를 연다. | 판사는 입력 마감 전에 수락된 지시가 개인 에이전트의 의견에 반영된 뒤, 달라진 제안과 앞선 판단을 함께 검토한다. 쟁점이 남고 회차가 남으면 다음 논의를 열고, 합의하거나 회차가 끝나면 최종 결정을 내린다. |
| 최종 여행안 | 판사 에이전트가 어떤 결정을 내렸는지 확인하고, 항목별 이유와 회차별 판단을 펼쳐 본다. | 핵심 여행 일정과 예산, 날짜별 장소·이동·활동을 보여 준다. 방장이 확정한 값은 `사전 확정`, 양립할 수 없는 필수 조건은 `미해결`, 근거가 부족한 항목은 `확인 필요`로 표시한다. |

## ROOM-05 · 방을 만들고 동행을 초대하는 흐름

처음 방문한 사람은 첫 화면에서 `여행방 만들기`를 누르고 닉네임과 총인원을 정한다. 아직 정해진 여행 정보가 없으면 나머지를 기본값 그대로 제출할 수 있다. 생성이 끝나면 방장의 브라우저에 `/r/<invite>/share`가 열린다.

| 장면 | 화면과 동작 |
| --- | --- |
| 방을 만들었다 | `여행방을 만들었어요`라는 제목 아래에 “함께 갈 사람에게 이 링크를 보내 주세요.”라는 안내와 읽기 전용 `여행방 초대 링크` 입력칸을 둔다. 입력칸에는 현재 서비스 주소에 `/r/<invite>`를 붙인 전체 주소가 보인다. 바로 옆에 `링크 복사`, 그 아래에 `내 여행 조건 입력`을 둔다. |
| 링크를 복사한다 | 성공하면 버튼 가까이에 `초대 링크를 복사했어요.`를 표시한다. 브라우저가 복사를 지원하지 않거나 권한을 거부하면 입력칸으로 초점을 옮겨 링크 전체를 선택하고 `링크 전체를 선택했어요. 복사해서 공유해 주세요.`라고 알려 준다. 사용자는 키보드나 모바일 선택 메뉴로 복사해 원하는 대화방에 붙여 넣는다. |
| 방장이 계속하거나 다시 공유한다 | `내 여행 조건 입력`을 누르면 같은 방의 기본 주소로 이동한다. 개인 조건 입력과 준비 완료 후 대기 화면에서 `초대 링크 공유`로 다시 열 수 있다. 입력 중이던 개인 조건은 돌아와도 남는다. 이미 준비한 방장에게는 공유 화면의 다음 동작을 `대기 화면으로`로 표시한다. 협상이 시작되었거나 결과가 나온 뒤 공유 주소를 다시 열면 현재 단계로 이동한다. |
| 초대 링크를 연다 | 처음 온 사람은 확정된 조건과 입장 인원을 보고 닉네임으로 입장한다. 정원에 도달했거나 입장이 닫혔으면 마감 안내를 읽는다. 이미 입장한 사람은 자기 조건 입력·제출 확인·대기·협상·결과 중 현재 단계로 돌아간다. |
| 방장용 공유 주소가 전달됐다 | 방문자와 일반 참가자를 같은 방의 기본 주소로 돌려보낸다. 다른 브라우저에서 방장의 주소를 열어도 방문자는 입장 화면을, 준비한 참가자는 자기 대기 또는 진행 화면을 본다. 준비한 참가자는 기존 대기 화면에서도 동행에게 보낼 링크를 복사할 수 있다. |
| 생성이나 조회가 실패한다 | 입력값은 보존하고 오류와 다시 시도할 방법을 보여 준다. 생성 응답을 받지 못해 같은 설정으로 재시도하면 처음 발급된 방의 공유 화면이 열린다. 공유 화면을 새로고침하거나 연결을 복구할 때도 같은 방을 조회한다. 존재하지 않는 초대 주소에는 링크를 확인하라는 안내와 `처음으로`를 표시한다. |

**확인 방법**

1. 새 브라우저에서 방을 만들고 팀 코드 입력 없이 공유 화면이 먼저 열리는지 확인한다. 복사한 주소를 별도의 세션에서 열어 초대받은 사람이 이름을 입력할 수 있는지, 방장용 주소를 전달한 경우에도 같은 입장 화면이 열리는지 확인한다.
2. 360px 너비에서 가로 스크롤 없이 링크와 두 동작을 확인한다. 키보드로 링크 입력칸, 복사, 다음 동작 순서로 이동하고, 복사 성공·권한 거절 각각에서 상태 문구를 보조기기가 읽을 수 있는지 확인한다. 화면을 주기적으로 갱신해도 링크의 선택 범위와 키보드 초점이 유지돼야 한다.
3. 방장이 복사를 건너뛰고 개인 조건을 적은 뒤 공유 화면을 다시 열어 같은 주소와 작성값을 확인한다. 준비를 마친 뒤에는 대기로, 협상이 시작된 뒤에는 현재 진행 단계로 복귀하는지 방장과 게스트 각각의 세션에서 확인한다.

## 여행 조건 입력

항목마다 기본 선택은 `에이전트에게 맡기기`다. `직접 입력`을 선택한 항목에만 입력창을 펼친다. 뒤로 갔다 돌아오거나 일시적으로 맡기기로 바꿔도 작성 중인 값은 복구할 수 있다. 맡기기로 제출한 항목에는 이전에 입력한 값을 보내지 않는다.

| 항목 | 직접 정할 때의 동작 |
| --- | --- |
| 여행 날짜 | `시작일`과 `종료일`을 지정한다. 날짜가 뒤집히면 종료일 옆에 수정 안내를 표시한다. |
| 1인당 최대 예산 | 수직선 형태의 슬라이더에 있는 손잡이 하나를 움직여 한 사람이 쓸 수 있는 최대 금액을 정한다. 현재 금액과 단위를 표시한다. 정확한 금액을 숫자로 입력하면 슬라이더도 그 값에 맞춰 움직인다. 요약에는 `1인당 최대 55만 원`처럼 한 금액을 표시한다. |
| 항공편 일정 | 가는 편과 오는 편을 구별해 날짜·시간과 알고 있는 노선 또는 편명을 입력할 수 있다. 편명을 모르는 참가자도 `가는 편은 첫날 오전, 오는 편은 마지막 날 저녁`처럼 원하는 시간대를 전할 수 있다. |
| 현지 이동수단 | `택시`, `대중교통`, `렌터카`를 선택지에 명시한다. 항공편을 정했어도 현지 이동수단은 따로 맡기거나 선택할 수 있다. |

## 판사 에이전트와 개인 에이전트의 성격

`판사 에이전트의 성격과 말투`와 `내 에이전트의 성격과 말투`는 각각 **공격성, 예의, MZ 감성** 세 가지 슬라이더와 `원하는 성격과 말투` 자유입력란을 제공한다. 각 슬라이더에는 항목명, 양 끝의 `0`과 `10`, 현재 정숫값을 표시한다. 손가락으로 끌거나 키보드 방향키로 한 단계씩 바꿀 수 있다. 방장이 자신의 에이전트를 설정해도 앞에서 정한 판사의 값은 보존한다. 다른 참가자도 각자의 에이전트를 독립적으로 설정한다.

개인 에이전트는 첫 제안과 토론 발언을 작성할 때마다 참가자가 쓴 자유 입력 원문과 기본 성향, 세 수치를 받는다. 판사도 조율 결과를 알리거나 토론을 열 때 방장이 정한 페르소나로 말한다. 예를 들어 판사는 `차분한 라디오 진행자처럼 말을 걸어 줘`, 내 에이전트는 `오랜 친구처럼 반말로 짧게 제안해 줘`라고 각각 설정할 수 있다. 첫 조율에서 바로 합의해도 두 화자의 표현을 대화 기록에서 확인할 수 있다. 발언 생성에 실패하면 정해진 제안·판단 내용을 기본 문장으로 표시한다. 판사의 말투를 바꿔도 같은 제안·근거에는 같은 판단 기준을 적용한다.

## 알림과 대화

- 파이터 모드가 시작되면 방에 머무는 참가자에게 모드 이름과 `대화 보기` 버튼이 있는 눈에 띄는 배너를 한 번 띄운다. 보조기기도 같은 내용을 한 번 읽는다. 화면을 떠났다가 돌아온 사람도 대화 입구를 찾을 수 있다. 기기 정책과 사용자의 설정이 허용하는 경우 소리나 진동을 더할 수 있다. 무음이거나 동작 줄이기를 켜도 배너와 버튼은 그대로 읽고 누를 수 있어야 한다.
- 공개 발언에는 화자 이름을 글자로 표시한다. 참가자의 제안과 발언에는 해당 개인 에이전트 이름이, 판사의 조율·판단과 최종 결정에는 `판사 에이전트`가 나타난다. 이전 발언을 읽는 중에는 읽던 위치를 유지하고 `새 발언 보기`를 제공한다.
- 개인 지시는 전송에 성공하면 `내 에이전트에게 전달됐어요`로 바뀐다. 에이전트는 다음 적용 가능한 발언이나 판단에서 이를 사용한다. 다른 사람의 화면에는 개인 지시 원문이나 보낸 이의 사적인 설명을 표시하지 않는다. 협상이 끝난 뒤 도착한 지시에는 마감 안내를 표시한다.
- 입력 오류는 해당 항목 옆에 수정 방법을 표시한다. 전송 실패 시 초안을 보존하여 다시 보낼 수 있다. 입장 불가 사유를 구분하며, 끊겼다가 연결되면 방의 상태·대화·결과를 복원한다. 대기와 협상 화면에서 중복 터치나 새로고침으로 제출과 발언이 중복되지 않아야 한다.

## 화면 및 접근성 확인

참고 이미지에서 흰 바탕, 옅은 회색 구분선, 짙은 본문과 주 버튼, 왼쪽 정렬된 제목, 넉넉한 여백을 가져온다. 모바일은 한 화면에 한 단계를 보여주고, 넓은 화면에서는 읽기 폭을 유지한다. 긴 입력 화면이나 채팅에서 하단 버튼이 마지막 입력칸 또는 메시지를 가리지 않아야 한다.

| 확인 장면 | 관찰할 결과 |
| --- | --- |
| 두 브라우저에서 방장과 초대받은 사람으로 입장 | 서로의 공개 정보는 같고 개인 설정과 개인 지시는 작성자에게만 보인다. 모두 맡기기와 일부 직접 입력 양쪽에서 제출할 수 있다. |
| 방장이 슬라이더로 1인당 최대 예산을 50만 원으로 정한 뒤 55만 원을 직접 입력하고, 참가자가 항공편 시간대와 현지 대중교통을 선택 | 슬라이더의 금액도 55만 원으로 바뀐다. 참가자는 회색 행의 자물쇠·확정 표시와 `1인당 최대 55만 원`을 읽을 수 있다. 항공편 일정과 현지 이동수단의 선택이 요약에 별도로 남는다. |
| 방장이 판사 에이전트와 자기 에이전트의 세 슬라이더를 서로 다른 값으로 조절하고 말투 지시도 다르게 제출 | 양 끝값 0·10과 중간값을 터치와 키보드로 선택할 수 있다. 파이터 모드에 등장한 두 화자의 발언은 각자의 수치와 자유입력 지시를 반영한다. |

## TURN-03 · 토론에서 앞선 입장을 다시 말할 때

서울 여행 실측에서 서윤의 첫 제안과 토론 발언은 같은 문장이었다. 두 참가자가 대화를 순서대로 읽을 때, 두 번째 발언만 들어도 서윤이 자기 예산 상한을 계속 지키려 한다는 점을 알 수 있어야 한다. [실측 발언 3번과 7번](../test/live-two-person-gemini-after.md)

| 토론에서 일어난 일 | 두 참가자가 읽을 발언의 예 |
| --- | --- |
| 서윤이 예산 상한을 처음 공개한다. | “1인 예산 상한으로 350,000 KRW를 제안합니다.” |
| 서윤이 앞서 공개한 같은 항목과 값을 유지한다. | “1인 예산 상한은 앞서 제안한 350,000 KRW로 유지하겠습니다.” |
| 민재가 택시에서 대중교통으로 양보한다. | “오, 그거 좋네. 현지 이동수단은 대중교통 쪽으로 양보할게.” 상대가 먼저 같은 값을 말했다 해도 민재 자신의 행동을 표현한다. |

각 예시는 문장 선택의 기준이다. 생성 문구가 새 비용 보장이나 근거를 덧붙이면 같은 항목·값·행동을 담은 검증된 표현으로 복구한다. 서윤의 격식체와 민재의 짧은 반말은 각자의 설정을 따르고, 두 참가자에게는 같은 공개문이 보인다. 개인 지시 원문과 사적인 이유는 공개 발언에서 제외한다.

기존 대화 목록에서 키보드로 이전 발언을 읽는 중 새 회차가 도착하면 읽던 위치에서 `새 발언 보기`로 이동할 수 있어야 한다. 새 발언 안내와 최종 여행안의 대화 기록에서도 화자 이름과 발언 본문만으로 최초 제안·재확인·양보를 구별할 수 있어야 한다.

## OPEN-04 · 두 사람이 처음 제안할 때

| 장면 | 두 참가자가 확인할 결과 |
