# 동행 · 여행 조율 구현 명세

## OPEN-04 · 첫 발언을 각자 직접 제안하는 말로 작성한다

기준은 `213567c5046e85bc906b49f8f2b692b306bcd2c5` 위의 TURN-03 작업 트리다. 변경 전 SHA-256 접두사는 graph `B13B1BA09C48`, tone `692BCD1C7BBF`, prompts `9A0F13447357`, test_persona `4AE11FF6638D`, 전체 재생기 `8D5AB4688C2F`, 시나리오 `8FD5306AE46A`다. [이전 실측](../test/turn-memory-gemini.md)의 자연 재생에서 생성·검토 9~16번 요청과 공개 3·4번을 비교한다.

1. 가장 중요한 기준은 조건과 행동의 정확성, 두 번째는 사용자가 지정한 실제 말투다. 첫 제안에서는 본인 선호를 나타내는 감탄·어휘·종결을 쓸 수 있다. 앞선 상대 발언을 상정하거나 비용·편의의 근거를 새로 덧붙일 수 없다. 페르소나에 조건을 덧붙이라는 요청이 있으면 승인한 조건 자체를 표현한다.
2. 기존 `Workflow.propose → participant_turn → render_speech → public_event` 경로에 적용한다. 확정된 제안 데이터와 사용자가 쓴 페르소나에서 첫 발화의 작성 요청을 만들고, 독립적으로 검증한 완결문을 게시한다. 원래 발언이 거부되면 승인 사실만으로 다시 쓴다. 필요한 피드백에는 한정된 사유 범주만 넣고, 거절 후보·모델 자유 텍스트·다른 사람의 정보를 전달하지 않는다. 동시 제안의 순서와 이후 협상 기억은 유지한다.
3. 첫 시도와 재작성 모두 사람이름·단어별 템플릿에 의존하지 않는다. 기존 값 치환, 조사, 개인정보, 협상 행동, 양방향 의미 검사를 그대로 적용하고 안전한 복구를 보존한다. 새 제안 경로에는 생성·검토 호출 횟수 상한을 두고 근거 없이 같은 호출을 반복하지 않는다. 기존 발화 출처와 저장·화면 API를 재사용한다. [ADR-010](../adr/travel.md) · [공개 흐름](travel-flow.md)
4. 기존 실측의 실패 양상, 다른 페르소나·안건, 검토 거짓 긍정·잘못된 값·개인정보·거부·연결 오류를 포함해 회귀 검사한다. 조건 파일·모델·45초 토론창을 그대로 사용한 자연 재생에서 두 첫 발언 모두 모델 작성문이어야 한다. 각 공개문이 해당 화자의 제안값과 행동을 보존했는지 원본 및 의미 검토와 대조하고 두 브라우저의 결과와 민재의 후속 양보까지 확인한다. 모형 응답, 문체 선택 복구, 새 방을 반복해 성공한 것만 뽑는 방식은 이 실측의 대체 증거가 될 수 없다.

두 번째 실측 이후 [ADR-011](../adr/travel.md)을 추가했다. 값이 있는 제안은 한 응답 안에서 값 앞뒤의 한국어를 모델이 자유롭게 지은 간결한 자기 제안과 독립된 다른 표현을 받을 수 있다. 조합 전후 형식·비공개 내용·중복 값·원래 행동을 확인하고 별도로 심사한 후보만 게시한다. 거부문을 잘라 쓰지 않는다. 중립적 검토가 복사한 인용과 문장부호 문제를 피하도록 검토 지시를 첫 발언에 맞춘다. 처음 선택과 수정에서 중복 문장을 제외하고 생성 최대 2회, 후보 의미 검토 최대 4회로 종료한다. 새 경로로 게시한 경우 생성된 필드와 입력값만으로 실제 텍스트를 재현할 수 있어야 한다.

첫 제안 작성·검토 호출에서는 Gemini의 구조화 출력 기능으로 필드의 자료형과 분류값을 요청 시점에 지정한다. 공개 가능한지 판단하는 책임은 여전히 서버의 값·행동·인용·개인정보 검사에 있다. [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output) · [generateContent 설정](https://ai.google.dev/api/generate-content#v1beta.GenerationConfig)

## TURN-03 · 페르소나와 발언의 연속성

기준은 `213567c5046e85bc906b49f8f2b692b306bcd2c5` 위 PAIR-02 작업 트리다. [기존 실측](../test/live-two-person-gemini-after.md)의 최종 원본 SHA-256은 `62b5b2aad5423cd86c9d5d77027d22213aa39413543dc2d3029d849ef58c68f4`이다. 변경 전 파일 SHA-256 접두사는 tone `B74A3796BB0BB9EF`, graph `F10CDF33272A1DBB`, store `78FEA994EE0B260C`, prompts `F3151D340517A3FF`, models `E720C57DB5CC958B`, test_persona `2415CD111226B713`, 재생기 `D37360025049E25A`다.

1. 방의 두 세션이 같은 공개 발언을 읽는 경로와 사용자가 지정한 원래 말투를 유지한다. 같은 통화의 두 예산 *상한*은 한도가 다르다는 사유만으로 양립 불가능하지 않다는 점을 판사 지시에 명시한다. 실제 비용·근거 확인은 계속 가능하다.
2. 기존 저장 이벤트를 문맥의 원본으로 삼는다. 최근 관련 공개 발언과 본인이 같은 안건에서 말한 입장만 짧게 가져와 협상·표현 요청에 전달한다. 첫 병렬 제안에서 다른 미래 발언을 보지 않는다. 자신의 최근 같은 안건에 게시한 **입장과 값**에 근거해 지키는 행동을 재확인으로 표현한다. 다른 화자, 변경된 값, 정보 확인·양보 등 다른 행동, 과거의 오래된 입장은 재확인 근거가 아니다. 비공개 지시·다른 사람의 페르소나·거부된 초안은 이 기억에 넣지 않는다.
3. 자유 발화에서 원안의 값과 행동을 정확히 전달한 문장이 불필요한 덧붙임 때문에 통째로 사라지는 실패를 줄인다. 별도로 생성한 짧은 핵심 발언 또는 원래 후보에 완결된 발언으로 존재하는 부분은 **그 자체를** 기존 안전·의미 검토에 통과시킨 뒤에만 게시한다. 생략한 부정·전제·조건이 뜻을 뒤집거나 양보를 제안으로 바꾸지 않아야 한다. 최근 공개문을 바꿔 쓰라는 이유로 새 이유·약속을 만들지 않는다. 자율적으로 생성한 표현과 서버가 구성한 복구 표현은 기록에서 구분한다.
4. 공개문이 모두 거절되거나 모델 지연이 발생해도 첫 제안, 앞선 입장 유지, 기존 제안에 대한 양보를 구별하는 한국어로 전달한다. 복구 단계까지 테스트하며 같은 문구를 무작위로 회전시켜 대화의 진척을 흉내 내지 않는다. 같은 방을 다시 읽거나 작업을 재시도할 때 미게시 발언을 기억하거나 과거를 다시 생성하지 않는다.

완료 확인은 일반 회귀 시험, 이전 실패 형태를 강제한 회귀 시험, 동일 입력·두 모델·45초 토론창·두 독립 세션으로 재생한 실제 방과 최종 화면을 사용한다. 실제 방의 제안 주제가 달라질 수 있으므로 기존 예산 첫 제안과 재확인도 실제 Gemini로 따로 재현해 공개 전문·호출 성공 여부·자유 생성과 복구 경로를 비교한다. 설계 결정은 [ADR-009](../adr/travel.md)와 [발언 흐름](travel-flow.md)에 기록한다.

## PAIR-02 · 두 참가자의 발언과 최종안 수정

기준은 커밋 `213567c5046e85bc906b49f8f2b692b306bcd2c5` 위의 작업 트리다. 변경 전 제품 파일 지문과 2인 실행 원문은 [기존 시험](../test/live-two-person-gemini.md)에 있다. 해당 실행기의 SHA-256 접두사는 `5790E0D701F3FC2F`, 기존 결과 화면은 `8EBF0FD07170E4AC`이다. [ADR-008](../adr/travel.md#adr-008--참가자-의사와-ai-제안의-출처를-판정과-공개-발언에-보존한다)

관찰할 우선순위는 참가자 의사와 발언의 정확성, 항목별 불확실성의 가시성, 실제 대기 시간이다. 기존 방 생성·입장·준비·개인 지시·최종 조회 API와 모델 분리를 유지한다. 저장/읽기 및 렌더링은 추가 정보가 없는 저장방도 처리한다. 공개 결과에 개인 지시 원문을 넣지 않는다.

| 검증 항목 | 완료 기준 |
|---|---|
| 1. 결정 출처 | 입력하거나 승인한 조건과 결정값의 관계를 검증한다. 개인이나 판사가 만든 다른 값, 자율 토론으로 바꾼 값, 근거 없는 자유 입력 추출값은 참가자 합의로 승격되지 않는다. 사전 확정값·필수 조건·예산 상한과 실제 지시에 따른 양보가 유지된다. |
| 2. 발언의 의미 | 기준 제안의 값과 협상 행동을 보존한다. 새 약속·검토 조건·최상급 판단 등을 추가한 발언이나 모순된 검토 결과는 게시하지 않는다. 단어 목록으로 의미를 판정하지 않는다. |
| 3. 페르소나 | 실제 값이 정확하게 한 번 들어 있는 후보의 형식을 복구하고, 필요한 경우 최대 한 번 짧게 수정해 재검증한다. 숫자·개인 정보·원래 행동 보호를 유지한다. 같은 방의 양보 시점에 민재의 반말을 실제 공개 기록에서 확인한다. |
| 4. 부분 검증 | 한 항목의 의견 불일치와 근거 부족이 함께 있으면 둘 다 공개한다. 일정에서 출처가 부족한 구체 장소는 검증됐다고 표시하지 않으며, 별도 날짜의 독립적으로 유효한 활동 또는 명시적으로 표시한 후보를 유지한다. |
| 5. 판정 시간 | 입력·응답량 또는 추론 비용을 줄이고 모델 전송 시간과 횟수를 측정한다. 원 실행의 478.28초·판사 시간 초과 4회와 비교한다. 시나리오·모델·토론 입력 시간은 그대로 사용하고 실제로 열린 토론 횟수도 공개한다. |

진입점은 두 브라우저 세션의 방 API다. 각 에이전트가 최초 제안과 지시를 구조화하고, 판사는 공개 제안과 이력으로 판정한다. 서버가 출처·예산·근거를 확인한 결과를 이력·최종안·결과 화면에 일관되게 전달한다. 네트워크 실패에도 기존 방 작업 재개, 중복 지시 방지, 잘못된 발언의 안전한 폴백을 유지한다. 재현 가능한 회귀 시험과 실제 모델 전송을 각각 기록한다.

두 차례의 수정 후 실측에서 서윤의 비용·효율 설명이 반복해서 거절돼 존댓말 기본문만 공개됐다. 값이 있는 참가자 발언의 경우 표현 모델이 자유문과 함께 사용자가 요청한 말높이와 짧은 반응 방식을 고른다. 자유문과 한 번의 수정이 모두 검증을 통과하지 못하면, 서버는 허용한 말높이·반응만 사용해 이미 정해진 값과 협상 행동을 말한다. 이 경로의 텍스트는 생성 후보에 적힌 근거나 사적 표현을 복사하지 않는다. 유효한 표현 선택도 얻지 못한 경우에는 일반 기본문을 사용한다. 실측에서 자유문 채택과 말높이 복구를 따로 집계한다.

제품 동작과 인수 기준의 원본은 [여행 조율 PRD](../prd/travel.md)다. 구현은 방 단위 트랜잭션, 개인별 서브그래프, 두 모드를 담당하는 판사에 관한 [ADR-001~003](../adr/travel.md)을 따른다.

## 방과 참가자

[TRIP-01 AC1·AC2](../prd/travel.md#trip-01-여행방과-조율). 브라우저는 같은 출처의 Flask API로 방을 만든다. 팀 개설 코드를 설정한 서버는 방 생성 시 코드를 확인한다. 초대받은 사람은 `/r/<초대 코드>`로 입장하고, API는 참가자 전용 동작을 요청할 때 방별 쿠키를 확인한다. 개인 설정과 지시는 소유자에게만 반환하고, 다른 참가자에게는 공개 상태와 발언을 제공한다. 클라이언트가 잠금 표시를 우회해 확정값을 바꾸려 해도 서버가 거절한다.

방 생성 시 확정 항목과 정원으로 좌석별 역할·임무를 생성한다. 생성 요청 안에서 처리하거나 같은 트랜잭션에 즉시 실행할 작업을 등록한다. 역할은 전원 준비 전에 저장하고 참가자가 입장하면 개인 입력과 연결한다. 입력 폼은 예산의 숫자와 슬라이더 값을 동기화하고 공통·개인 말투를 별도로 저장한다. 기본 말투 수치는 각각 5이며 기존 프리셋 문자열도 읽는다.

## 동시성과 재시작 계약

[TRIP-01 AC1·AC2·AC4·AC5](../prd/travel.md#trip-01-여행방과-조율), [TRIP-02 J2·J4](../prd/travel.md#trip-02-판사-에이전트).

- **재전송과 시작**. 브라우저는 방 생성·입장 요청 전에 요청 키를 보관하고 개인 지시에는 별도 ID를 붙인다. 성공 응답 유실 후 같은 키가 오면 기존 방·참가자·지시 번호를 반환한다. 마지막 준비 상태와 첫 실행 단계는 같은 DB 트랜잭션에서 기록한다.
- **작업 복구**. 실행기는 단계·턴·만료 시각을 가진 작업 임대를 획득한다. 외부 모델은 DB 잠금 밖에서 호출한다. 응답 시점에 임대 소유권과 단계가 일치할 때만 결과·단계별 고유 이벤트·다음 단계를 함께 저장한다. 실행기는 시작할 때와 주기적으로 만료된 작업을 재개한다. 호출 직후 중단되면 외부 비용은 다시 발생할 수 있다.
- **개인 지시 마감**. 참가자별 접수 번호를 증가시키고 마지막 입력 창을 트랜잭션으로 닫아 마감 번호를 고정한다. 한 발언은 한 항목을 수정한다. 발언 생성 중 추가 지시가 오면 다음 턴을 열어 접수순으로 하나씩 반영한다. 공개 발언과 처리한 번호를 함께 저장하고, 마감 번호까지 처리한 뒤 판사를 호출한다. 마감 후 새 지시는 거절하고 이미 접수한 요청의 재전송에는 기존 번호를 돌려준다. 브라우저는 폴링으로 입력 가능 여부와 전달 상태를 갱신한다.

## 모델과 근거 계약

생성자는 좌석별 임무를 배정한다. 개인 에이전트는 검색 조건, 여행 제안, 한 차례의 협상 행동을 결정하고, 판사는 좌석별 제안을 비교해 항목별 판단과 일정을 작성한다. 검색 모델은 사실을 뒷받침하는 인용 구간을 반환한다. 공개 발언을 만들 때는 화자가 직접 쓴 페르소나 원문과 이미 결정한 내용을 사용자 메시지로 함께 전달한다. [역할별 프롬프트](../../travel_app/prompts.py) · [설계 결정 ADR-005](../adr/travel.md#adr-005--여행-조율-단계별-모델-지시문을-한-모듈에서-관리한다) · [호출 검증 기록](../test/agent-prompts.md)

[TRIP-01 AC3·AC5](../prd/travel.md#trip-01-여행방과-조율). LangGraph에서 개인 조율 서브그래프를 병렬 실행한다. 개인 제안·검색에는 `MEMBER_MODEL`(기본 `gemini-3.1-flash-lite`), 판사에는 `MEDIATOR_MODEL`(기본 `gemini-3.8-flash`)을 사용한다. 검색 에이전트에는 질의에 필요한 여행지·날짜·출발지·시간대 또는 숙소 위치와 음식 종류를 전달한다.

Google 검색 응답에서 출처 URL과 조회 시각을 보존한다. 운임은 인원·왕복 조건을 포함해 PRD의 모든 조건과 인용 내용을 대조한 뒤 공개한다. 식당은 해당 지점의 메뉴 판매 근거, 장소는 목적지와 소재지를 확인한다. 검색 실패와 불충분한 근거는 확인 필요로 처리한다. 새 의미 판정 기록이 없는 이전 방의 출처도 확인 필요로 표시한다. 서버는 결정 저장 직전 원래 확정값을 다시 적용하고 필수 조건의 충돌을 확인한다. 잠정 값과 이유는 회차별로 저장한다.

## TRIP-02 · 판사 에이전트

[TRIP-02 J1~J4](../prd/travel.md#trip-02-판사-에이전트). `judge` 노드에는 모든 좌석의 최신 제안·중요도·근거, 이전 판단, 현재 모드와 남은 토론 횟수를 전달한다. 마감한 회차의 개인 지시는 반영된 제안만 전달한다. 판사의 말투와 비공개 지시 원문은 판단 입력에서 제외한다. 마지막 토론 뒤에는 남은 횟수 0을 전달하고 `final` 노드가 검증된 판결을 한 번 게시한다.

기존 `mediator` 요청·응답과 모델 설정 키, 저장 단계명과 이벤트 ID, 말투 프리셋과 브라우저 초안을 계속 읽는다. 과거 방의 시스템 화자 표시는 공개 응답에서 판사로 변환한다. 참가자가 작성한 이름과 문장, 발언 순서는 보존한다.

## SEM-01 · 모델의 의미 판정

1. 개인 에이전트의 검색과 토론 중 재검색은 같은 근거 검토를 사용한다. 검색 응답에서 실제 HTTPS 출처 한 곳에 연결된 구간만 후보로 정하고, 제한된 수의 후보와 공개 검색 조건을 모델에 한 번에 보낸다. 식당은 지점·음식·식이 조건, 장소는 실제 소재 도시와 요청 조건, 운임은 동일 성인 한 명의 왕복·세금 포함·수하물 조건을 확인한다. 운임의 금액·노선·날짜·통화·시간은 동일 인용에 있는 값과 대조한다. 검토 결과가 모호하거나 구조가 틀리면 해당 출처를 확인 필요로 둔다.
2. 판사는 판정 시점의 필수 활동을 누락 없이 검토한다. 확정적으로 모두 수행하는 일정과 택일·취소·불확실한 제안을 의미로 구별한다. 서버는 모델 판정이 실제 요구와 제안 또는 유효한 날짜·장소의 일정에 연결됐는지 확인한다. 날짜 밖의 행이나 검증되지 않은 장소를 근거로 삼지 않는다. 필수 활동의 충족이 확인되지 않으면 미합의로 둔다. 모드와 화자의 페르소나는 필수 조건의 강도를 바꾸지 않는다.
3. 공개 발언의 의미 검토는 가격 조회 의향과 새 최저가 보장을 구별한다. 출처 없는 수치, 비공개 문구와 발언의 실제 값은 기존 구조 검사로 보호한다. 확인된 새 근거는 저장·재접속 후에도 동일하게 표시한다. 예전 근거는 보존하되 이전 판정만으로 새 확인 표시를 만들지 않는다. 조회와 DB 트랜잭션에서 외부 호출을 수행하지 않는다.
4. 결과 화면에서 한 검색에 확인된 출처와 확인되지 않은 출처가 함께 있으면 각각의 링크와 인용문에 어떤 판정이 적용되는지 글자로 표시한다. 두 종류의 출처 링크를 모두 열 수 있어야 한다.

[설계 결정 ADR-006](../adr/travel.md#adr-006--인용문의-의미와-필수-활동-충족-여부를-모델이-판정한다) · [검색·활동 판정 검증 기록](../test/semantic-review.md)

## 검증 방법

**PERS-01 · 발언의 페르소나.** 개인 에이전트와 판사는 공개할 내용이 정해진 뒤에 각자의 모델로 발언을 작성한다. 발언 요청에는 해당 화자가 설정한 자유 입력 원문과 기본 성향, 공격성·예의·MZ 감성 수치가 들어간다. 좌석별 첫 제안은 병렬로 준비하고, 여행 조건·예산·검색·판정에는 기존 검사를 적용한다. 발언 생성을 위한 외부 호출은 방 트랜잭션을 열기 전에 수행한다. [ADR-004](../adr/travel.md#adr-004--화자의-자유-입력으로-공개-발언을-생성한다)
