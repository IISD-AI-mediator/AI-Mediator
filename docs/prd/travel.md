# 동행 · 여행 조율 제품 요구사항

동행은 2~8명이 각자 원하는 일정과 예산을 제안하고 하나의 여행안을 정하는 웹앱이다. 이미 예약한 항공편처럼 바꿀 수 없는 조건을 먼저 고정하고, 나머지는 개인 에이전트가 제안한다. 판사 에이전트는 전원의 제안과 근거를 비교해 합의한 내용과 끝까지 풀리지 않은 쟁점을 함께 남긴다.

여행 검색의 범위는 조회 당시 출처로 확인한 선택지와 가격까지다. 실제 예약과 모든 판매처에 걸친 최저가 보장은 범위 밖이다.

## 사용자와 여행 조건

- **방장**은 방을 만들고 정원과 공통 확정 조건, 판사의 말투를 정해 초대 링크를 공유한다. 방장도 참가자 한 명으로서 자기 조건을 제출한다.
- **참가자**는 이름을 정해 입장하고, 각 항목을 에이전트에게 맡기거나 직접 입력한다. 희망 조건의 중요도와 추가 요청을 적을 수 있고, 방장이 확정한 항목은 값과 잠금 표시를 읽을 수 있다.
- **여행 조건**에는 여행지, 시작일·종료일, 숙소, 1인당 최대 예산, 항공편 일정과 현지 이동수단이 포함된다. 예산 슬라이더와 숫자 입력은 같은 통화·상한액 하나를 표시한다. 가는 편과 선택적인 오는 편에는 편명·공항·현지 일시 또는 희망 시간대를 적을 수 있다. 택시·대중교통·렌터카는 항공편과 별도로 선택한다.
- **말투**는 판사와 각자의 개인 에이전트에 따로 설정한다. 공격성·예의·MZ 감성을 각각 0~10으로 조절하고 원하는 말투를 적을 수 있다. 말투는 공개 발언에 반영되고, 같은 제안과 근거에는 같은 판단 기준을 적용한다.

## TRIP-01 여행방과 조율

| 인수 기준 | 사용자가 확인할 수 있는 결과 |
| --- | --- |
| AC1 · 방 생성 | 첫 화면에서 ‘여행방 만들기’와 ‘사용법’을 각각 열 수 있다. 방장이 닉네임·정원·확정 조건을 제출하면 초대 링크가 하나 생기고, 같은 요청을 다시 보내도 같은 방으로 돌아간다. 배포된 앱에서 새 방을 만들려면 팀 개설 코드가 필요하다. |
| AC2 · 초대와 준비 | 초대받은 사람은 공통 확정 조건과 입장 인원을 보고 참여한다. 입장 수와 준비 수가 따로 보이며, 전부 맡기기와 일부 직접 입력 모두 제출할 수 있다. 확정값 변경 요청은 거절된다. 마지막 두 명이 동시에 준비하거나 한 사람이 연속 제출해도 정원이 차고 전원이 준비했을 때 조율이 한 번 시작된다. |
| AC3 · 제안과 검색 근거 | 각자의 제안과 중요도가 판단에 반영된다. 외부 확인이 필요한 항목에는 출처와 조회 시각이 붙는다. 1인 왕복 운임은 인원·왕복 여부·노선·날짜·시간대·통화·운임 조건이 출처와 일치할 때 관찰 가격을 표시한다. 식당은 요청 지역의 해당 지점과 메뉴, 장소는 해당 도시와 장소가 확인돼야 한다. 근거가 부족하거나 조회에 실패하면 ‘확인 필요’로 표시한다. |
| AC4 · 대화와 개인 지시 | 의견이 모이면 결과가 열리고, 충돌하면 파이터 모드 시작 알림과 순서대로 읽을 수 있는 공개 대화가 나타난다. 참가자는 최소 20초 동안 자기 에이전트에게 지시할 수 있다. 마감 전에 접수된 지시는 접수순으로 발언과 다음 판단에 반영되며, 마감 후 새 지시에는 마감 안내가 보인다. 재접속해도 같은 알림이나 발언이 중복되지 않는다. |
| AC5 · 결과와 복구 | 결과에는 일정·예산과 날짜별 장소·이동·활동, 항목별 이유와 회차별 판단이 남는다. 사전 확정값을 지키고 필수 조건·예산 상한·접근성·검증된 근거를 일반 선호보다 우선한다. 정해진 회차가 끝나면 합의한 항목을 확정하고 양립할 수 없는 필수 조건은 ‘미해결’로 남긴다. 오류 후 재시도하거나 다시 접속해도 앞선 발언과 결정이 보존된다. |

## TRIP-02 판사 에이전트

| 인수 기준 | 사용자가 확인할 수 있는 결과 |
| --- | --- |
| J1 · 조율 모드 | 두 사람이 같은 교통수단을 제안하면 전원의 제안 뒤에 판사의 판단이 이어진다. 두 사람 모두 같은 최종 여행안과 판사 명의의 결정 한 건을 본다. |
| J2 · 파이터 모드 | 판사가 남은 쟁점을 알려 논의를 연다. 참가자가 교통과 예산에 대해 차례로 지시하면 두 제안의 변경이 각각 발언에 반영된다. 판사는 최신 제안과 이전 판단을 함께 검토하고, 합의하거나 회차를 소진하면 최종 결정을 내린다. |
| J3 · 화자와 비공개 지시 | 사용법·방 설정·협상·결과에서 판사와 개인 에이전트의 역할을 글자로 구별한다. ‘조율 모드’와 ‘파이터 모드’의 공개 발언·판단 이력·결과에서 판사의 이름이 일치한다. 개인 지시 원문과 사적인 설명은 다른 참가자에게 공개되지 않는다. |
| J4 · 이전 방과 재시도 | 이전 버전의 방과 작성 중인 입력을 다시 열 수 있다. 과거 진행자의 발언은 판사로 표시하고 참가자의 이름·발언과 회차 순서를 보존한다. 이전 방에도 같은 검색 근거 기준을 적용한다. 판사 오류 후 재시도해도 최종 결정은 한 번만 보인다. |

## 공통 인수 조건

- **두 참가자의 발언과 최종안**. 두 사람이 맡긴 항목을 AI가 채우면 'AI 제안'으로 표시한다. 참가자가 직접 제출한 조건과 개인 지시로 수용한 조건은 실제 결정값에 연결한다. 발언의 말투를 바꿔도 처음 제안한 값과 양보·제안·확인 행동을 보존한다. 의견 충돌과 검색 근거 부족이 겹치면 같은 항목에 두 사유를 함께 전한다. 날짜별 활동은 장소와 근거에 따라 일정 반영, 확인할 후보 또는 미정으로 표시한다.

- **권한과 입력 복구**. 초대 링크만 가진 방문자는 참가자 전용 데이터에 접근할 수 없고, 참가자는 자기 방에서 자기 에이전트에게만 지시할 수 있다. 입력 오류는 해당 항목 옆에 수정 방법을 표시한다. 뒤로 가기와 전송 실패 후 초안을 복구하고, 맡기기로 제출한 항목은 이전 입력을 제안에 반영하지 않는다.
- **접근성**. 360px 화면과 키보드만으로 방 생성부터 결과 확인까지 진행할 수 있다. 화면 갱신 중 초점과 채팅을 읽던 위치를 유지한다. 터치 대상은 44px 이상, 본문 대비는 4.5 대 1 이상이다. 새 단계와 오류는 보조기기로 식별할 수 있고, 무음에서도 대화 시작을 알 수 있다. 동작 줄이기 설정에서는 인사 애니메이션을 정지 화면으로 대체한다.

화면별 동작과 예시는 [화면 설계](../design/travel-flow.md), 인수 기준별 검증 방법은 [구현 명세](../design/travel-implementation.md)에 있다.
